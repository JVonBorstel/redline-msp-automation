# B-61 RMM and Intune mock adapters and device reconciliation

Status: **mocked** (RMM and Intune mock adapters with builders, a PSA asset reader, the reconciliation workflow and CLI, tests). Read-only throughout; no real adapter exists and every real selection fails closed. Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-EP-01` (device inventory reconciliation, RMM vs Intune vs PSA). Controls: `C-27` (one client per unit of work), `C-21`. Depends on `B-18` (adapter base, bindings), `B-16` (PowerShell bridge; a listed dependency in `map/roadmap.json`, not called by this item's code). Standards: `STD-ER`, `STD-FX`, `STD-ID`. Decisions: `D6-01` (mocks shaped after Datto RMM, vendor-neutral interfaces), `D6-26` (existing RMM components are listed read-only and never run until vetted).

## Why

One true device list per client, which billing, patching and security all need. A laptop that is in Intune but has no RMM agent is not patched by the RMM; a device the PSA bills for that no system has seen in two months may be in a drawer or gone; the same machine twice in the RMM is counted twice. Each of these is found by comparing three lists that each system keeps on its own.

## Behaviour

- **RMM adapter** `adapters/rmm/` (`RmmAdapter`, `RmmMock`, `build_rmm_adapter`): built for one client from its `rmm` binding (`external_id` = the RMM site uid). `get_site`, `list_devices`, `get_device`, `get_device_audit` (the serial is in `bios.serialNumber`), `list_open_alerts`, `list_jobs`, `get_job`, `list_components`. Typed results, never raising (STD-ER-1). A record of another site is dropped and a lookup of one answers exactly like an absent one. No method runs a job, quick job or component, and none changes a device.
- **Intune adapter** `adapters/intune/` (`IntuneAdapter`, `IntuneMock`, `build_intune_adapter`): built from the client's `m365` binding (`external_id` = the tenant GUID); `list_managed_devices`, `get_managed_device`. Read-only.
- **PSA assets** `workflows/device_reconcile/psa_assets.py` (`PsaAssetsMock`, `build_psa_assets`): Autotask-shaped `ConfigurationItems` of one company, built from the client's `psa` binding. It lives in the workflow because `adapters/psa/` and `fixtures/psa/` are B-18's.
- **Fixtures** `fixtures/rmm/`, `fixtures/intune/`, `workflows/device_reconcile/psa_assets/` (Contoso Dental seeded, Fabrikam Capital the clean twin), pinned to `asOf` 2026-10-22T12:00:00Z, each `SOURCES.md` with a per-field Verified/UNVERIFIED table. The RMM and PSA files each hold a decoy record of the other client that carries this client's first name and serial.
- **Reconciliation** `workflows/device_reconcile/` (`python -m workflows.device_reconcile <client> [--as-of ...] [--clients <dir>]`):
  - records with a usable serial are matched by serial (case and spaces ignored; `placeholder_serials` in `config.json` count as no serial);
  - a record without a usable serial is then matched by name (case ignored, DNS suffix dropped) when exactly one device carries that name; with two candidates it is not guessed and stays its own device; two records with different serials are never merged by name;
  - every record is in exactly one device, and each mismatch is listed: `only-in-one-system`, `stale` (RMM `lastSeen` or Intune `lastSyncDateTime` older than `stale_days`, 30, or unreadable), `duplicate` (one system holds the device more than once);
  - the three adapters must be of one client, and the RMM site's `autotaskCompanyId` (when set) must be the PSA reader's company, or nothing is compared (`ReconcileError`);
  - the RMM account's components are listed with `vetted: false` and `run_by_program: false`.
- **Selection** `build_sources(client, config_dir=...)` builds all three from `config/clients/<client>.json`; any binding other than `mock` fails closed with `real adapter not configured` (the reason names the system, e.g. `rmm: real adapter not configured`); the CLI then exits 2.

## Acceptance

- **B61-1** Devices are matched across RMM, Intune and PSA assets per client by serial, then name; each mismatch type (only in one system, stale, duplicate) is listed.
- **B61-2** Counts reconcile to the fixtures; no device of another client is ever compared.
- **B61-3** Real adapter selection fails closed (`real adapter not configured`).
- **B61-4** The RMM mock follows the public Datto RMM API shape (sites, devices, alerts, jobs, components), each field marked Verified or UNVERIFIED; existing RMM components are listed read-only and never run by the program until vetted into the registry (D6-01, D6-26).

Tests: `tests/py/devices/test_b61_reconcile.py`, every acceptance test named `test_b61_<k>_...` (run: `uv run --frozen pytest -p no:cacheprovider tests/py/devices`).
