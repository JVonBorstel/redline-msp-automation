Inventory: `W-TOOL-06` (approval queue), `W-CMP-05` (audit evidence), `W-SD-02` (ticket triage), `W-M365-11` (tenant baseline). Controls: `C-41`, `C-45` (synthetic data, honest labels), `C-08`. Standards: STD-TS, STD-DC.

## Why

The demo is the one artifact the reader sees. Until now it was a script that a person checked by hand, so a late change to any command, output line or denial reason could break it without anyone noticing. This item makes it a tested artifact: every typed command runs in a test, offline, against a temp state folder, and the test checks the exact lines the presenter points at. Demo v2 also tells the W1 story about one person (Priya Nair, synthetic, ticket `T-3101`): the lead verifies her by a callback before approving, she gets a plain-words notice draft, and any lead can pause the lever.

## Behaviour

### Demo v2 (`docs/DEMO.md`)

- The story follows T-3101 (Priya Nair at Contoso Dental) from the ticket to the audit chain. The proposal id `P-d01c53bdf1dc` is deterministic (a hash of lever, client and parameters), so the script names it.
- Every stateful command names the state folder explicitly (`--state .tmp/demo`, `-OutDir .tmp/baseline-contoso`), so one textual substitution moves the whole demo to a temp folder.
- Step 6 now holds, inside the same five minutes: **6a** approve without a verification (refused), then record a callback on the number on file (source: PSA contact record) and approve; **6b** `python -m workflows.notify P-d01c53bdf1dc --state .tmp/demo` drafts Priya's notice; **6c** `pause`, a dry-run invoke that is denied because the lever is paused, then `resume`. The step 6 fallback adds the missing-verification denial and the `--verified callback-on-file` execute (B-02). The 6b fallback shows the notice template.
- The timing table is re-cut (steps 1-5 and 7 shorter, step 6 80 seconds, close 50 seconds) and still sums to 5:00.
- The honesty lines and the week-one plan are byte-identical to the previous version. Every line that shows a number (findings, percentages, corpus size) says fixture-based.

### Smoke test (`tests/demo/test_b10_demo_smoke.py`)

- Parses `docs/DEMO.md`: every fenced `powershell` block under "Before the room" and steps 1-8, each tagged `main` or `fallback` by the line before it.
- Runs the main blocks in document order in one temp state root, and the fallback blocks in a second, fresh root (a fallback replaces the live step, so it starts from what the presenter would have). Each block runs as one `pwsh -NoProfile -NonInteractive -File` script from the repo root, with `.tmp/` replaced by the temp root. After each `uv` or `pwsh` line the exit code is recorded.
- Three lines are not run, and each must still be in the doc: `scripts/clean.ps1` (it would delete the repo's `.tmp`; the smoke test starts from an empty folder instead) and the Phase 1 and Slice B suites (separate suites, run by CI). The smoke test's own line is skipped too (no recursion).
- `Invoke-Item` is shadowed by a function that checks the file exists and does not open a browser.
- The approval page command (`python -m ui --state .tmp/demo`) is started as typed with `--port 0` added; the test reads the address it prints and drives the page over 127.0.0.1 only: sign in as lead-lee, approve Priya's card with no verification (refused, still pending), approve with `callback-on-file` + `psa-contact` (executed, banner names the verification), reject one seeded baseline proposal, and press **Verify chain** after steps 7, 8 and the restore. The process tree is stopped at the end.
- Each block has an expectation entry: the exit code of each `uv`/`pwsh` line and the markers its output must contain. A block without an entry, or an entry without a block, fails.
- Nothing is written to the repo's `.tmp/demo`, `.tmp/triage` or `.tmp/baseline-contoso`, and the committed fixtures are unchanged (checked before and after).

### Runner (`tests/demo/Test-Demo.ps1`)

- `pwsh -NoProfile -File tests/demo/Test-Demo.ps1` runs the pytest file through `uv run --frozen` and prints `Demo tests: N passed, M failed`. A run over 120 seconds counts as one failure. Exit 0 only when nothing failed.

## Acceptance

- **B10-1** The smoke test runs every typed command of DEMO.md steps 1-8 (and the fallbacks) in a temp state folder, offline, and checks each expected marker (`"status": "ok"`, the two denial reasons, `OK: <n> records`, `BROKEN at seq`).
- **B10-2** The script adds, inside the same five minutes: the callback verification before approve, the notice draft after execute, and `pause` then a denied invoke then `resume`; the timing table still sums to 5:00 or less.
- **B10-3** The smoke test finishes in under 120 seconds on the laptop and prints `Demo tests: N passed, M failed`.
- **B10-4** Honesty lines and the week-one plan are unchanged in substance; every number shown is still labelled fixture-based.

Tests: `tests/demo/test_b10_demo_smoke.py`, one or more `test_b10_<k>_...` per id. Run with `pwsh -NoProfile -File tests/demo/Test-Demo.ps1` (or `uv run --frozen pytest tests/demo`). The folder is not in the default pytest run (`testpaths` is `tests/phase1`), so Phase 1 stays fast.
