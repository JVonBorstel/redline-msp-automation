# B-20 Prompt library and prompt standards

Status: **built** (`prompts/__init__.py`, three prompt files under `prompts/library/`, `prompts/STANDARDS.md`, checked by `tests/py/prompts/test_b20_prompts.py`). Nothing calls a model; no workflow uses the library yet.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-TOOL-03` (prompt standards and libraries). Controls: `C-12` (untrusted input wrapping), `C-41` (evaluation gate before promotion), `C-16` (provider abstraction). Standards: STD-DC, STD-SC, STD-VR. Depends on nothing; `B-22` and `B-25` build on it.

## Why

Prompts today are strings in `core/gateway/ollama.py`. A reviewer cannot see what each one asks for, which version a model saw, or whether untrusted ticket text can leak out of its data block. A library makes each prompt a reviewed, versioned file with a declared contract.

## Behaviour

- `prompts.load(task, version)` reads `prompts/library/<task>.v<n>.md`, checks it and returns a frozen `Prompt`. There is no default version. `prompts.load_library()` loads every file and fails as a whole on one bad file.
- Front matter keys, exactly: `task`, `version`, `description`, `owner`, `status` (`draft` | `active` | `retired`), `inputs`, `output_schema`, `eval`. Each input has `name`, `trust`, `why`, `max_chars`, and `source` when untrusted.
- `prompts/library/LOCK.json` pins each released file's SHA-256 (LF-normalised). An edited released file fails to load.
- `prompts.render(prompt, values)` takes exactly the declared inputs, wraps untrusted ones with `core.guard.wrap_untrusted`, and returns the prompt id, hash, system and user text. A retired prompt loads but does not render.
- `prompts.output_errors(schema, value)` checks a parsed model reply against the declared schema subset.
- Shipped: `classify.v1` (active, gated by `evals/triage/report.py`), `summarize.v1` and `reason.v1` (draft, `eval: none-yet`). Their system text starts with the exact instruction the gateway sends today.

## Acceptance

- **B20-1** Each prompt is a versioned file `prompts/library/<task>.v<n>.md` with front matter (task, version, inputs, output schema, owner; plus description, status, eval). The loader refuses an unknown task or version, a file whose name and front matter disagree, a missing or unknown key, an input with no `why` or size limit, an input named like a personal identifier, an unbounded string in the output schema, an `active` prompt with no eval, a file not in the lock, a lock line with no file, and a released file edited in place.
- **B20-2** Every prompt that takes untrusted text places it only inside the `wrap_untrusted` block: the placeholder appears once, alone on its own line, in the user section only, and the system section says the text is data, not instructions. The test checks each library file by rendering a canary and finding it only inside one correctly labelled block. Forged delimiters in the text stay inside the one block. Trusted values are one line and never re-expanded.
- **B20-3** `prompts/STANDARDS.md` covers structure (PS-1), untrusted text (PS-2), minimum-necessary inputs (PS-3, BA-4), output schemas (PS-4), versioning (PS-5) and how a prompt change goes through evals (PS-6, C-41). Every repo path it names exists.

Tests: `uv run --frozen pytest -p no:cacheprovider tests/py/prompts`.

## Not in scope

- Wiring `core/gateway/ollama.py` to read from the library (owned elsewhere; v1 text already matches, so the switch changes nothing the model is told).
- A CI threshold gate on prompt promotion (C-41 stays partial).
- Content redaction before a prompt (C-25, planned). The personal-identifier check is on input names only.
