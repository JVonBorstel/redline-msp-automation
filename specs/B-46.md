# B-46 Business email compromise containment plan and inbox-rule audit

Status: **mocked** (levers, mock fixtures, workflow, CLI, tests). Proposes containment; executes nothing itself. Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-SEC-04`, `W-M365-05`. Controls: `C-05`, `C-06`, `C-07`, `C-30`, `C-32`, `C-35`. Depends on `B-45`. Standards: `STD-PR`, `STD-LV`, `STD-TS`.

## Why

A compromised mailbox is contained in minutes, with a person approving each step. The classic sign of business email compromise is an inbox rule the attacker adds: forward invoices outside, delete the helpdesk's warning, or hide replies in a folder nobody opens.

## Behaviour

- **`inboxrule.list`** (`levers/registry.d/inboxrule.json`, `levers/python/inboxrule.py`): class read, `R0`, approval none, technician role. Reads `fixtures/tenant/<client>/inbox-rules.json`, a family file in the Graph `messageRule` shape with each mailbox's folders. Params `upn` (optional: one mailbox, default every mailbox of the client) and `flagged_only`. Each rule gets `flags`, one per reason, of four kinds:
  - `external-forward`: `forwardTo`, `redirectTo` or `forwardAsAttachmentTo` names an address whose domain is not in the client's `internal_domains` (all are flagged when the client's domains are not on record);
  - `delete`: `delete` or `permanentDelete` is true;
  - `rss-folder`: `moveToFolder` or `copyToFolder` names a folder whose name starts with "RSS";
  - `obscure-folder`: the folder is one users rarely open (a fixed list in the module, such as "Conversation History"), has no letter or digit in its name (".", ".."), or is not on record.
  A client with no file gets `{"value": [], "note": ...}`; the note says an empty list is not an all clear.
- **`inboxrule.disable`** (`R2`, approval lead, undo `inboxrule.enable`) turns one rule off; **`inboxrule.enable`** (`R2`, `undo_of: inboxrule.disable`) turns it back on. A write handler gets the client's base state only (STD-LV-8), so the change is recorded there under `inboxRuleChanges[<rule id>] = {mailbox, isEnabled}`, and `inboxrule.list` shows the effective `isEnabled`. An entry exists only while it differs from the family file, so disable and enable are exact inverses and the B-41 rollback proposes `inboxrule.enable` for an applied disable.
- **`contain(runner, client, upn, requester, incident=None, queue=None)`** (`workflows/bec/`): one target only. It reads the user's rules through `inboxrule.list`, then builds the steps in `workflows/bec/config.json` order: block sign-in (`user.disable`), revoke sessions (`user.revoke-sessions`), reset MFA (`user.reset-mfa`), then one `inboxrule.disable` per flagged rule that is on, in rule order. Each step is dry-run through the runner (audited) and queued as a pending proposal (source `triage`, ref the incident id) for a lead. A flagged rule that is already off is listed as `already-met` with nothing proposed. `executed` is always false.
- **Evidence and timeline**: each flagged rule becomes an evidence row (rule id, mailbox, name, flag kinds and reasons, created and modified times, the `inboxrule.list` audit seq). `timeline(plan, audit_path)` verifies the audit chain first and refuses to build on a chain that does not verify; it returns a header line (format `incident-timeline/1`, a notice that declaration and notification belong to the client and its counsel) and one event per rule time and per audit record of the plan, oldest first, for this client only. `write_timeline` writes it as JSON Lines to `<state>/bec/timelines/<client>/<incident>.jsonl`.
- **Prompt**: `prompt_text(plan)` is the only text meant for a model: step labels, statuses and the count of flagged rules. No rule id, name, address or time. Rule names are untrusted (C-12): a name the injection detector flags is replaced by a fixed sentence in the evidence and the timeline.
- **`audit_rules(runner, client, identity)`**: the read-only client-wide audit (`W-M365-05`): every flagged rule of every mailbox.
- **CLI**: `python -m workflows.bec plan <client> <upn> [--as tech-ana] [--incident ID] [--prompt] [--state DIR]` and `python -m workflows.bec audit <client>`.

## Acceptance

- **B46-1** `inboxrule.list` (R0) flags rules that forward externally, delete, or move to RSS or obscure folders; `inboxrule.disable` (R2, undo `inboxrule.enable`) turns one rule off
- **B46-2** the containment plan for one user proposes, in order: block sign-in, revoke sessions, reset MFA, disable the flagged rules; each a dry-run proposal needing approval; one target per plan
- **B46-3** the plan's evidence (rules found, times) goes into an incident timeline (B-48 format) and never into a prompt

Tests: `tests/py/bec/test_b46_bec.py`, named `test_b46_<k>_...`. Tests that build a whole plan dry-run `user.revoke-sessions` (PowerShell) and skip without `pwsh`.

## Known limits

- Mock only. The `messageRule` field names, the rule-id shape and the Graph permission names (`MailboxSettings.Read`, `MailboxSettings.ReadWrite`) are UNVERIFIED: no Graph page was read for this change.
- Rule times (`createdDateTime`, `lastModifiedDateTime`) are INVENTED for the mock. A real adapter would take them from the mailbox audit log, which this repo does not model.
- B-48 is not built. The `incident-timeline/1` format is defined here; B-48 should adopt it or migrate these files.
- The write levers cannot see the family file, so they cannot check that a rule exists; the plan reads it first (STD-LV-9), like `backup.retry-job`. Disabling a rule that the snapshot already has off adds an entry; a later enable then removes it and the rule stays off. The plan never proposes that: it lists such a rule as `already-met`.
- The queue has no `bec` source (`core/queue` is not this item's file), so proposals use `triage`.
- Approving `user.disable` and `user.reset-mfa` still needs the recorded requester verification (C-30) and, under a runner policy, `reset-mfa` (R3) needs two leads. The plan does not collect them; the approval page does.
- The obscure-folder list is a fixed choice made on the fixtures, not tuned.
