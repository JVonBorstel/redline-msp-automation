# B-09: Roadmap-to-issues exporter and change-fragment folder

Owns: `tools/roadmap_issues.py`, `tools/fold_changes.py`, `docs/changes/README.md`, `tests/py/tools/test_b09_tools.py`, `specs/B-09.md`, `docs/changes/B-09.md`.

Both tools are offline, deterministic and use only the standard library. Data comes from `map/roadmap.json` (fixture-based planning data).

## Acceptance

- **B09-1**: `uv run python tools/roadmap_issues.py --wave W1` prints one `gh issue create` command per item of the wave: title `B-nn: <title>`, labels (`wave:`, `size:`, `owner-only` when set), milestone (the wave id), and a body holding every roadmap field. It runs nothing itself.
- **B09-2**: `--format ado-csv` prints the same items as an Azure Boards import CSV with the columns work item type, title, tags, iteration path and description.
- **B09-3**: `tools/fold_changes.py --wave W1 --dry-run` prints the ledger edits the wave's fragments would make and changes nothing. Without `--dry-run` it appends them, and a second run changes nothing (idempotent).
- **B09-4**: an unknown wave is refused with a message naming the known waves.

## Notes

- Quoting in `gh` commands is POSIX (`shlex.quote`); UNVERIFIED in PowerShell, where the commands should be run from a POSIX shell or adapted.
- The ADO work item type is `User Story` (Agile process); UNVERIFIED against the MSP's process template.
