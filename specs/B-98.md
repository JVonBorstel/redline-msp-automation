## Design notes
- Status comes from files. A change note's `Status:` word is shown as the item's *kind* and compared, not trusted.
- An inventory row's status is an upper bound: it is derived from the roadmap items that list it, and one item may cover only part of a row. The report says so.
- "Built" is "the evidence files are present and a test is tied to them". The audit does not run tests (the suites do).
- Findings carry a severity: error (map claims more than files show), stale (map claims less), gap (a required file is missing), info.
- Exact line-ending handling: generated files are compared with CRLF normalised to LF, so a Windows checkout with autocrlf compares equal.
