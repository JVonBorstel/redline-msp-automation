# B-11 One-ticket trace leave-behind (T-3101, granular to macro)

Status: **built** (`docs/TRACE_T3101.md`, checked by `tests/py/docs/test_b11_trace.py`). A document over steps built in `B-03`, `B-04` and `B-05` (and the runner gates of `B-02`); it adds no code.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-IDM-02` (MFA reset, the person), `W-TRN-02` (explaining the AI honestly to a client). Controls: `C-45` (synthetic data, honest labels), `C-08` (audit chain), `C-30` (requester verification). Depends on `B-03`, `B-04`, `B-05`.

## Why

The reader keeps one page that shows the mantra in one concrete case: Priya Nair (synthetic), one person at one client (Contoso Dental), ticket T-3101, traced through each step to the practice, the managed service provider and the community. It doubles as the script an account manager would use to explain the system honestly (`W-TRN-02`).

## Behaviour

`docs/TRACE_T3101.md` is plain English for a reader who is not technical:

- Status line first (STD-DC-1), the prototype line and a page-level "every number is fixture-based" label (STD-DC-2).
- A step table (the ticket, the triage proposal, the verification, the approval, the audit record, the notice draft) and an impact table (Contoso Dental, the MSP, the community). Every row ends with a "Rests on" cell of map ids.
- The commands to see it run, each copied from `docs/DEMO.md`.
- A "What this does not prove" list.

## Acceptance

- **B11-1** One page (at most 850 words) with one row each for the ticket, the triage proposal, the verification, the approval, the audit record, the notice draft, Contoso Dental, the MSP and the community. Every row cites at least one id, only of the kinds `W-`, `C-`, `EU-`, `ISO-`, `HO-`, and every cited id resolves: `W-` in `map/inventory.json`, `C-` in `map/controls.json`, `EU-`/`ISO-`/`HO-` as a defined id in `docs/map/05-governance.md`. The page names Priya Nair and T-3101 as synthetic, and its factual claims match a fixture run of T-3101 (triage proposes `user.reset-mfa` for Priya with the callback line; an unverified execute is refused; the verified, approved execute records the verification and masks the phone; the notice draft says her password is the same and names Lee; the verifier reports `OK: 2 records`). The three impact rows cite the item's inventory ids and controls (`W-IDM-02`, `W-TRN-02`, `C-45`, `C-08`, `C-30`) between them.
- **B11-2** Every command on the page (fenced block lines and inline code that runs `uv run`, `pwsh` or `python -m`) appears verbatim in `docs/DEMO.md`, so the demo smoke test (`B-10`) covers it. Every line that still carries a digit after ids and code are removed says `fixture-based`, and the page carries the page-level label. It states plainly that there is no real tenant and no real callback, and that nothing is sent. The checkers are themselves tested against a bad page.
- **B11-3** Every acronym (two or more capital letters, outside code and ids) is spelled out at its first use, as `words (ACR)`. The checker is tested against an unexplained acronym.

Tests: `tests/py/docs/test_b11_trace.py` (run with `uv run --frozen pytest tests/py/docs -o addopts=`; the default `pytest` run is `tests/phase1` until `B-06`).
