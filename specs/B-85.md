# B-85 Bicep core: Key Vault, managed identity, Log Analytics; secrets doc

Status: **source and static checks only.** The Bicep is written and its text is tested; nothing was compiled, linted, validated, what-if'd or deployed (no Azure CLI or Bicep on the build machine). Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems.

Inventory: `W-TOOL-08` (secrets and managed identity management), `W-PRJ-05`. Controls: `C-39`, `C-40`, `C-10`. Decision `D6-10` (one vault per environment). Standards: `STD-SC`, `STD-DC`. Depends on nothing.

## Deliverables

- `infra/bicep/core/main.bicep` (resource-group scope) and `modules/`: `logAnalytics.bicep`, `managedIdentity.bicep`, `keyVault.bicep`, `diagnosticSettings.bicep`.
- `infra/bicep/core/main.dev.bicepparam`, `main.prod.bicepparam`: placeholders and plain names only.
- `infra/bicep/core/README.md`: the build, lint, validate and what-if steps a human runs.
- `docs/SECRETS.md`: managed-identity-first pattern, secret naming, how an adapter binding names a secret reference, rotation stays human.
- `tests/py/infra/test_b85_bicep_core.py`: static checks (text only), functions named `test_b85_<k>_...`.

## Security properties asserted in source

Key Vault: `enableRbacAuthorization: true`, `enableSoftDelete: true` with 90-day retention, `enablePurgeProtection: true`, `publicNetworkAccess: 'Disabled'`, network ACL default `Deny`, tags, no access policies, no secret/key resource, role assignment Key Vault Secrets User to the managed identity (no administrator role). Workspace: `disableLocalAuth: true`, retention set. Diagnostic settings: `AuditEvent` and metrics to the workspace only. Every taggable resource takes `tags` (environment, owner, dataClass, project). Parameter files: no secret-looking key or value; only placeholders and plain names.

## Acceptance

- **B85-1** modules build with `az bicep build` and lint clean; Key Vault uses Azure RBAC, soft delete and purge protection; no secret value in any parameter file. **Only the second half is verified** (static tests). Build and lint are UNVERIFIED and are human steps in `infra/bicep/core/README.md`.
- **B85-2** `docs/SECRETS.md` shows the managed-identity-first pattern and how an adapter binding names a secret reference; rotation stays a human task.
- **B85-3** nothing is deployed: the test scans `infra/`, `scripts/`, `.github/workflows/` and `levers/` for create/deploy commands and finds none.
- **B85-4** one Key Vault per environment (dev, prod), secrets named `client-<id>-<purpose>`, access by managed identity with RBAC; per-client vault only by contract, recorded on the client record (D6-10).

Tests: `uv run --frozen pytest -p no:cacheprovider tests/py/infra`. The checkers are themselves tested by weakening a good vault in memory (each missing property is flagged) and by planting secret-looking values.

## Known limits

- The tests read text; they do not parse Bicep. A syntax error, wrong property name or wrong API version passes them.
- API versions and the built-in role id are from memory (UNVERIFIED).
- No private DNS zone, and no Log Analytics private-link scope: with vault public access disabled, reaching the vault needs a private endpoint plus DNS that this template does not provide.
- Role for the people who set and rotate secrets is not in the template (human task).
- No adapter reads `credential_ref`; it is a proposed shape.
