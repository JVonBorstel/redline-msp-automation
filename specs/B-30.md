# B-30 Password reset and Temporary Access Pass with out-of-band delivery

Status: **built** on the **mock** tenant (`levers/powershell/CredentialOps/`, `core/levers/oob.py`, `levers/registry.d/credential.json`, `tests/py/levers/test_b30_oob.py`). Nothing here has run against a real Entra tenant.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-IDM-01`, `W-ONB-05`. Controls: `C-10`, `C-30`, `C-06`, `C-07`, `C-11`. Depends on `B-28`, `B-16`, `B-19`. Standards: `STD-LV`, `STD-SC`, `STD-AU`, `STD-PS`. Decisions in force: D6-06 (callback on file plus the client's authorized contact; no privileged accounts), D6-07 (identity changes are R3).

## Why

Password help is the most common lockout fix and the step help-desk attackers talk their way through. The secret must never touch the AI: not a prompt, a result, a queue line, an audit record or a notice.

## Design

- Two PowerShell levers in module `CredentialOps` (runtime `powershell`, registry fragment `levers/registry.d/credential.json`): `user.reset-password` (`Reset-UserPassword`) and `user.new-tap` (`New-UserTap`). Both: `R3`, `class: write`, `approval: lead`, `verification: "requester+contact"`, `reversibility: reversible`, param `upn`.
- The Python runner keeps every check (B-28): two distinct signed-in leads, callback-on-file record naming the number's source, the client's authorized contact, privileged-target refusal. The module refuses a privileged target again (second lock).
- **The value.** Generated in PowerShell with `RandomNumberGenerator` (password 20 characters with four character classes; TAP 8 letters and digits, look-alikes removed). It is written once, to `<oob root>/<client>/<target id>-<password|tap>.json` (`$env:REDLINE_OOB_DIR`, else `.tmp/oob`), and nowhere else. The bridge forwards `REDLINE_OOB_DIR` to the child (one line in `_ENV_ALLOWED`).
- **Reading it.** `core/levers/oob.py`: `read_delivery(reader, client, target_id, type, requester=...)` hands the value to a human technician or lead scoped to the client (optionally only the named requester), once; an agent, a person of another client, an expired or malformed file is refused. Nothing in `core` imports this module except tests and the human-facing reader.
- **Tenant effect (no value).** Password: `passwordProfile.forceChangePasswordNextSignIn = true` and `pendingCredentials.password = {type, singleUse, expiryMinutes}`. TAP: one `temporaryAccessPassAuthenticationMethod` (`isUsableOnce: true`, `lifetimeInMinutes`) and `pendingCredentials.tap`.
- **TAP lifetime.** The shortest the tenant policy allows: optional `authenticationMethodsPolicy.temporaryAccessPass.minimumLifetimeInMinutes`, else the UNVERIFIED default 10; a policy `state` other than `enabled` refuses. A password handoff stays readable for 60 minutes (mock window).
- **Convergence.** While a credential of that type is pending the diff is empty and no second value is issued. Dry-run (`-WhatIf`) generates and writes nothing.
- **Result data** (`InvokeResult.data`): `target_id`, `credential_type`, `expiry_minutes`, `delivery: "out-of-band"`. The runner's audit record carries the diff, so the pending marker's path (target id and type) and `expiryMinutes` are the audit entry that a credential was issued; the value is in no record.
- **Notices.** `workflows/notify/templates/user.reset-password.md` and `user.new-tap.md` tell the person that a technician gives the value separately and that it is never in the message.

## Acceptance

- **B30-1** `user.reset-password` and `user.new-tap` are R3 and need requester verification; the generated value goes only to the out-of-band channel (mock: a file under .tmp/oob/ readable by the requesting technician) and never into the lever result, the queue, the audit, a notice or a prompt
- **B30-2** a sweep test runs both levers end to end and finds no secret-shaped value in any audit record, proposal, result object or log
- **B30-3** the audit records that a credential was issued (type, expiry, target id) and nothing else
- **B30-4** both levers declare `verification: "requester+contact"` (B28-8) and refuse targets holding a privileged directory role; a TAP is single-use with the shortest lifetime the tenant policy allows (D6-06)

Tests: `tests/py/levers/test_b30_oob.py`, `test_b30_<k>_...`. Run with `uv run --frozen pytest tests/py/levers/test_b30_oob.py`. The PowerShell-backed tests skip without `pwsh` 7.4+.

## Limits and open points

- UNVERIFIED (no vendor page read): Graph field names and the real policy minimum and default length of a Temporary Access Pass; the mock uses `isUsableOnce` and `lifetimeInMinutes`.
- "Prompt" and "queue" are covered by construction and by the sweep (the value is only in the out-of-band file; the queue holds only the upn). No prompt builder reads the folder.
- The queue cannot execute a `requester+contact` lever until B-65 wires the policy and the contact confirmation, so the sweep adds proposals to the queue but runs the levers through the runner directly.
- A pending marker has no clock, so a never-used credential blocks a new one until a later revoke lever clears it. The value is still readable once from the out-of-band file within its window.
- The mock channel is a file with no operating-system permissions; the reader check is in `oob.py`. A real channel replaces it.
