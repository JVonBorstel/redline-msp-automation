# B-82 SQLite queue and append-only audit store

Status: **built** (`core/queue/sqlite_store.py`, `core/audit/sqlite_store.py`, `tests/py/storage/test_b82_sqlite.py`). Offline, stdlib `sqlite3` only, synthetic data only. **Not wired in:** the JSONL stores stay the default (B82-3). Nothing was run on a network file system, on a non-Windows machine, or at production volume.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-TOOL-06`, `W-CMP-05`. Controls: `C-08`, `C-09`, `C-39`, `C-07`. Depends on `B-42` (per-client audit chains). Standards: `STD-AU`, `STD-PR`, `STD-PY`.

## Why

The JSONL approval queue and audit chains rely on a file lock and one writer at a time. With many leads deciding and many jobs running at once, the file approach is slow and easy to get wrong. SQLite gives atomic transactions, a write lock that works across processes, and triggers the database itself enforces, without adding a dependency or a server.

## Job queue (`core/queue/sqlite_store.py`, `SqliteJobQueue`)

- `enqueue(client, kind, payload, idempotency_key, max_attempts=5, delay_s=0)` returns `EnqueueResult(job, created)`. Same (client, key) and same kind and payload: the existing job, `created=False`. Same key, different kind or payload: `QueueConflict`. Keys are per client.
- `claim(client, worker, lease_s=30, kinds=None)` leases the oldest due job (ordered by due time, then id). Each claim increments `attempts`. A job whose lease has expired is claimable again; one whose lease expires on its last attempt is dead-lettered by the next claim (`last_error` says why).
- `heartbeat(job, lease_s)`, `complete(job, result)`, `fail(job, error, retry=True)` act only if the caller holds a live lease: same job id, client, owner and attempt number (the fencing token), and the lease has not expired. Otherwise `LeaseLost`, nothing changes. A late finisher is refused even if nobody has re-claimed the job yet.
- `fail` requeues with delay `backoff_base_s * 2**(attempts-1)` capped at `backoff_cap_s` (defaults 5 s and 300 s, no jitter), or dead-letters when `attempts >= max_attempts` or `retry=False`. Error text is redacted (`core.audit.redact`) and cut to 2,000 characters.
- `requeue_dead(client, job_id)` is a person's decision; it resets attempts. A `done` job is final (trigger). Jobs are never deleted.
- `get`, `list`, `dead_letters`, `counts` are per client. A client id must match the repo's client id pattern (the same check the audit router uses); `_msp` and reserved Windows names are refused.

## Approval store (`SqliteApprovalStore`)

- Stores the existing `core.queue.store.Proposal` model unchanged (its id contract and validators still apply).
- `add` is idempotent. `decide(client, id, approver, approve, verification=None, auth=None)` moves `pending` to `approved` or `rejected` with the compare-and-set update; the loser of a race gets `AlreadyDecided` (with the current status). `SelfApproval` when approver equals requester. `finish(client, id, ok)` moves `approved` to `executed` or `failed` only.
- Triggers refuse any other status move and any change of id, client or requester, even from raw SQL.
- **Bookkeeping only.** Role, client scope, the runner's re-check and the audit record of a decision are still `ProposalQueue`'s job; this store does not replace them and nothing calls it yet.

## Audit store (`core/audit/sqlite_store.py`, `SqliteAuditStore`)

- `append(...)` has the arguments and normalisation of `AuditLog.append` (mode `invalid`, event and actor-kind fallbacks, redaction, request id) and returns the record. For equal inputs and an equal timestamp the record is byte-identical to the JSONL writer's (tested against `AuditLog` with its timestamp pinned). The timestamp comes from the store's clock.
- Chains: one per client id that passes the router's `valid_client_id`; everything else goes to `_msp` (as `AuditRouter` does). Each chain has its own `seq`, `prev_hash` and head.
- Storage: `audit_records(chain, seq, hash, prev_hash, line)` where `line` is the canonical JSON; `audit_heads(chain, seq, hash)` is the stored head pin.
- **Database-enforced:** triggers refuse UPDATE and DELETE on both tables; refuse an INSERT whose `seq` is not head+1 or whose `prev_hash` is not the head hash (no fork, no gap); advance the head by one after each insert; refuse a head change other than "one further, to an existing record's hash".
- **Verification** (`verify(client, expected_head=None)`, `verify_all()`, `python -m core.audit.sqlite_store verify <db> [--client C --pin SEQ:HASH]`): dumps the chain's lines and runs `core.audit.chain.verify_chain` on them against the stored head, so "intact" means exactly what it means for JSONL. Then checks an optional external pin (which may be older than the chain: the chain must contain that exact record), then checks the six guard triggers exist with unchanged SQL. A chain that verifies but lost its triggers is reported broken. Exit codes: 0 intact, 1 broken, 2 unreadable.
- `export_chain(client, dest)` writes `<client>.jsonl` and `<client>.jsonl.head`, byte-compatible with the JSONL store; `python -m core.audit.verify` accepts them. `import_jsonl(client, log, head)` verifies a JSONL chain first and loads it into an empty chain; `append` then continues it.
- Concurrency: every append is one `BEGIN IMMEDIATE` transaction (WAL, `synchronous=FULL`, `busy_timeout` 10 s by default); a lock not released in time raises `SqliteAuditStoreError` (an `AuditError`), failing closed with nothing written.

## Database basics (both modules)

- WAL is switched on at open and checked; any other result is an error. A new connection per operation, so one store object is safe to share across threads.
- Migrations are numbered tuples in `MIGRATIONS`, recorded per component in `schema_migrations(component, version, applied_ms)` (components `queue` and `audit` can share one file). Applied inside one `BEGIN IMMEDIATE` transaction (all or nothing); the version is re-read under the lock so two processes opening a new file both succeed. A database whose version is newer than the code is refused. Never edit a released migration.
- Time: an injectable `Clock` returning an aware `datetime`; stored as UTC millisecond integers (queue) or the audit record's ISO string.

## Not in scope

- Switching the default (needs a DECISIONS entry, B82-3), wiring `ProposalQueue`, `LeverRunner` or the UI to these stores, a worker loop, scheduling, or a CLI for the job queue.
- Audit rows for queue events (enqueue, claim, dead-letter, decision) are not written. Today the audit records of decisions come from `ProposalQueue`.
