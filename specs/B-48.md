# B-48 Incident and recovery fact packs and timeline export

Status: **mocked** (read-only timeline export and four fact packs over offline fixtures and a per-client audit chain; no firewall, SASE gateway, backup product, alert source or DNS registrar is called). Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems.

Inventory: `W-SEC-07` (incident declaration and breach notification), `W-BDR-07` (ransomware or disaster recovery decision), `W-SEC-09` (firewall and SASE rule changes), `W-VND-06` (domain and DNS registrar changes). All four are never-automate entries in `governance/never-automate.json`. Controls: `C-34`, `C-08`, `C-27`. Depends on `B-42` (one audit chain per client: `audit/<client>.jsonl` plus its head pin). Standards: `STD-AU`, `STD-DC`, `STD-TS`. The MSP profile rows: `MP-27` (Fortinet firewall), `MP-28` (SASE, vendor UNKNOWN). Not-now rule: `NN-05`.

## Behaviour

- `python -m workflows.timeline export --client <id> --audit-dir <state>/audit [--since T] [--until T] [--ticket T-nnnn ...] [--incident ID] [--text]` prints one client's incident timeline in format `incident-timeline/1`, the format B-46 (PR #60) defined in `workflows/bec`: JSON Lines, a header line first (`format`, `notice`, `client`, `incident`, `target`, `audit_chain`), then one event per line (`at`, `kind`, `source`, `ref`, then facts), oldest first. B-48 adopts it unchanged and only adds keys (header: `window`, `tickets`, `sources` (per source: status read, empty or absent, rows read, rows in the window), `withheld`, `dropped`, `rule_changes`; events: the facts of each source). `target` is null because the export is client-wide. `--text` prints the same timeline as Markdown for a person. Exit 0 = printed; 2 = bad input or missing source; 3 = the audit chain did not verify (nothing printed on stdout).
- `python -m workflows.timeline pack <breach|recovery-point|firewall|dns> --client <id> [--audit-dir DIR] [--since T] [--until T]` prints one fact pack as JSON. `breach` needs `--audit-dir` (it reads the chain, verified first). `--since`/`--until` mean at-or-after / at-or-before on every pack that takes them: `breach` and `firewall` window their rows, `recovery-point` takes only `--until` (the cutoff), `dns` takes neither; an option a pack cannot honour is refused with exit 2.
- The module opens files for reading only and writes nothing. It imports no lever runner, queue, approval or notify code.

## Acceptance

- **B48-1** The export reads exactly one client's chain, `<audit-dir>/<client>.jsonl`, and verifies it against its head pin before reading anything else. A broken chain, a missing chain or a missing head pin stops the export (exit 3 or 2) and nothing is printed on stdout. Rows come from three sources: audit records (seq, time, event, lever, mode, status, agent, actor kind, approver), alerts through `AlertsMock` (id, time, source type, severity, category, entity; never title or description) and firewall/SASE log lines. Ticket ids come from `--ticket` (each must be in the client's own `fixtures/tickets/<client>.json`; another client's id answers like an absent one) and from `ticket_id` params in the chain. Ticket subject and body are never copied. A contoso export holds no Fabrikam alert, ticket, device or audit record, and a record inside the chain that names another client is dropped and counted.
- **B48-2** Four fact packs: `breach` (W-SEC-07: alerts by severity, entities seen with first and last time, SOC case ids, lever executes from the verified chain), `recovery-point` (W-BDR-07: per asset, each successful backup job with its boot check, the latest one and the failures after it), `firewall` (W-SEC-09: every configuration change and SASE tunnel event from the log fixture), `dns` (W-VND-06: per domain, owner, SPF present, DMARC policy, DKIM selectors published). Each pack lists facts and gaps only: `readOnly: true`, `leversRegistered: []`, `proposals: []`, no recommendation field. No lever in the registry matches `breach.*`, `firewall.*`, `sase.*`, `dns.*`, `registrar.*`, `recovery.declare*` or `dr.*`, and the never-automate gate refuses such names.
- **B48-3** The first line of the export is the header whose `notice` is B-46's notice, unchanged: "Facts only. Whether this is a reportable incident or breach, and who is notified, is decided by the client and its counsel, not by this tool or the MSP." The first line of the `--text` view is that sentence, and so is the `decision` field of every pack. A test keeps `FORMAT` and `NOTICE` equal to `workflows/bec/config.json`.
- **B48-4** Firewall and SASE rows come from `workflows/timeline/fixtures/fortigate/<client>.log`, a synthetic key=value log shaped like a FortiGate event log (field names cited from the FortiOS 7.4.0 Log Message Reference, messages 44547 and 39947; `workflows/timeline/fixtures/SOURCES.md`). A line from a device not listed for the client is dropped and counted. Free-text fields flagged by the injection detector are withheld. Every firewall configuration change row is marked `human-only (NN-05)` and the export ends by saying rule changes stay human.

Tests: `tests/py/timeline/test_b48_timeline.py` (`uv run --frozen pytest -p no:cacheprovider tests/py/timeline`).

## Known limits

- The log fixture is invented in the cited shape; the 10-digit `logid` values, the `devid` values and the exact field order are UNVERIFIED (only the field names and message titles were read from the reference).
- The SASE vendor is UNKNOWN (MP-28); SASE tunnel events reuse the FortiGate VPN event shape as a stand-in.
- No eval set: the item owns no `evals/` folder and the export makes no judgement to score. Row counts in the tests are fixture-based.
- DNS registrar history has no source in this repo; the `dns` pack lists it as a gap.
