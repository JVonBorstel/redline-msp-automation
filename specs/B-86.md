## Acceptance

- **B86-1** Function app, Logic App and Automation account modules, plus the storage account the function host needs. Written in source: user-assigned managed identity from core on every compute resource (never system-assigned), no account keys (`allowSharedKeyAccess: false`), host storage by identity, FTP and SCM publishing credentials off, Automation `disableLocalAuth: true`, Logic App `state: 'Disabled'`, tags, no secret or key resource, no secret-looking literal, parameter files are `<placeholders>`. **Build and lint are UNVERIFIED** (human steps in the compute README).
- **B86-2** `infra/azure-pipelines.yml` mirrors `ci.yml` (the same suite scripts and the same pytest line, checked against `ci.yml` by the test so drift fails), adds the eval gate, a Lint stage, a WhatIf stage (validate and what-if), a manual approval stage (`ManualValidation`, server job, timeout rejects) and a Deploy stage that is disabled (`condition: false`) and only echoes. Order is Test, Lint, WhatIf, Approval, Deploy, with each depending on the one before. No deploy command appears anywhere in the file, comments included. **The pipeline has never run.**
- **B86-3** `docs/BRANCHING_RELEASE.md` covers branches, pull request rules, versioning (`STD-VR`), rollout rings R0 to R3 (`CM-5`) and rollback (`CM-6`), the infrastructure pipeline, a freeze checklist, and an UNVERIFIED list. `CM-5` and `CM-6` are labelled planned.

Tests: `uv run --frozen pytest -p no:cacheprovider tests/py/infra`. The checkers are tested by weakening a good function app and a good pipeline in memory (each weakening is flagged) and by planting secret-looking values. The B-85 deploy-command scan (`tests/py/infra/test_b85_bicep_core.py`) also covers the new files under `infra/`.

## Known limits

- The tests read text; they do not parse Bicep or YAML. A syntax error, a wrong property name or a wrong task input passes them.
- API versions, SKU, runtime string, role id and Azure DevOps task versions are from memory (UNVERIFIED).
- No diagnostics for the compute resources, no private endpoints, no VNet integration.
- The eval gate step is added in the pipeline only; `ci.yml` does not run it (editing `.github/**` is the owner's).
