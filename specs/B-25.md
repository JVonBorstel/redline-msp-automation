# B-25 Draft replies with KB citations and closure follow-up drafts

Status: **built** (workflow, CLI, eval, tests). Sending stays human (HO-9); nothing here sends anything. Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory (impact chains): `W-SD-05` (draft reply from the knowledge base), `W-SD-09` (closure confirmation and follow-up). Controls: `C-12` (untrusted input), `C-26` (per-tenant retrieval, citations, refusal when no source), `C-41` (eval gate), `C-45` (honest labels). Governance: `HO-9`, `AIR-4`, `EU-1`. Depends on `B-20` (prompt standards; no prompt is needed because no model is called) and `B-21` (Phase 2 gold set).

## What it does

`python -m workflows.replies reply|closure <ticket> --state <dir>` writes a draft to `<dir>/replies/<ticket>.<kind>.md`.

- **Reply:** scan the ticket for injection; run `kb.search` through the lever runner (agent identity, the ticket's client, audited); build the draft only from sentences of the returned articles read from the same client's KB, each followed by `[<article id>]`; validate with `check_citations`; or return `no draft: ...`.
- **Closure:** for a `resolved` ticket only: "Your ticket T-nnnn is now marked resolved", the fix (technician's line, or the matched KB guide cited), "Please check that it works", and the way back (the client's fast-path number from `fixtures/notify/contacts.json`, "we will reopen your ticket").
- Ticket free text is never copied into a draft. It is only used as search keywords.

## Acceptance

- **B25-1** Every sentence of a reply draft ends with `[KB-...]` and every cited id is an article of the ticket's own client (ids from `kb.search`, text from that client's tenant KB; `check_citations` finds no problem). With no source (no search hit with at least 2 keyword matches, or nothing searchable) the result is exactly `no draft: no source article` and nothing is guessed. A ticket flagged by the injection detector gets `no draft` and no search. A search the runner denies gives `no draft` with the denial reason and an audit record. The search is audited as the agent. Drafts are deterministic. The validator rejects an uncited sentence, two sentences under one citation, an unknown id and another client's id.
- **B25-2** A closure draft (resolved tickets only) says the ticket is resolved, states the fix in plain words (technician line or cited KB guide), asks the person to check, and gives the client's fast-path number and a reopen offer; at most 120 words, Flesch-Kincaid grade 8 or lower (test heuristic), no secret-shaped value, no address, no other client's number. A client without a fast-path contact, an unresolved ticket, or an unsafe fix line is refused. Both kinds of draft start with exactly `Draft. A person reviews and sends this.`. The package imports no mail, socket, HTTP, subprocess or model-gateway module and defines no send function, so code never sends (HO-9). The CLI writes only `<state>/replies/` and the audit log.
- **B25-3** Eval on the gold set (210 synthetic Phase 2 tickets): citation coverage 100% and zero cross-client citations, written to `evals/replies/report.md` labelled fixture-based; the test checks the committed report equals a fresh run. Source recall, wrong-article drafts and false drafts are reported, not gated.

Tests: `tests/py/replies/test_b25_replies.py` (run with `uv run --frozen pytest -p no:cacheprovider tests/py/replies`). Eval: `uv run --frozen python -m evals.replies.report`.
