# B-45 Phishing triage, message trace and quarantine release

Status: **mocked** (rules-only triage workflow, two PowerShell levers over offline mail-flow fixtures, eval, tests; no Defender, INKY or Exchange Online is called). Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems.

Inventory: `W-SEC-03`, `W-M365-03`, `W-M365-04`. Controls: `C-12`, `C-13`, `C-14`, `C-05`, `C-06`. Depends on `B-43` (untrusted-text pattern, eval pattern) and `B-16` (PowerShell bridge). Standards: `STD-LV`, `STD-SC`, `STD-TS`, `STD-FX`.

## Behaviour

- `python -m workflows.phishing --client <id> [--reports PATH]` prints one verdict draft per reported message (exit 0; 2 on bad input; "nothing to triage" when the file is empty).
- Two shapes, one path: a Defender user-reported shape and an INKY "Report Phish" shape each map into `ReportedMessage`; analysis, verdict, draft and lever hints are shared.
- Analysis reads `Authentication-Results`, `From`, `Reply-To`, `Return-Path`, URLs (split, never requested) and attachment names (content dropped). Weights and thresholds are constants in `workflows/phishing/phishing.py`: high-confidence phish at 6 or more, suspicious at 2 or more.
- Subject, From, body and link text are scanned with `detect_injection`; they never feed the verdict, appear only inside `wrap_untrusted`, and a flagged report's text is withheld with no lever suggested.
- `message.trace` (R0, technician) lists every recipient of one message in the client's own mail flow. `quarantine.release` (R2, lead approval, dry-run by an agent) releases one held message to one of its own recipients; `MailFlowOps` refuses `HighConfPhish` and `Malware` (one list, `$script:ReleaseRefused`).

## Acceptance

- **B45-1** A reported message is analysed from headers and URLs as data only (no URL is fetched, no attachment opened); the verdict draft cites the header fields used.
- **B45-2** `message.trace` (R0) and `quarantine.release` (R2) levers; release is refused for messages with a high-confidence phish or malware verdict.
- **B45-3** The injection corpus emails (hidden instructions) are flagged and get no lever; verdict accuracy is reported fixture-based (`evals/phishing/report.md`).
- **B45-4** The user-reported message fixture is shaped like an INKY phish report (MP-21; cited, unverified fields marked UNVERIFIED) beside the Defender shape, and both take the same verdict path.

Tests: `tests/py/phishing/test_b45_phishing.py` (`uv run --frozen pytest -p no:cacheprovider tests/py/phishing`). Eval: `uv run --frozen python -m evals.phishing.report`.

## Known limits

- Rules only; a phish from a genuine, well-authenticated account with a clean link is scored likely-clean. The draft is for a person to check.
- Lookalike detection compares the first domain label after simple digit swaps; it is not an edit-distance or homoglyph check.
- Every vendor shape and cmdlet name is UNVERIFIED (`fixtures/mailflow/SOURCES.md`).
- A released message cannot be taken back by a lever (`undo: null`); the notice says how a person removes it.
