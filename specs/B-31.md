# B-31 LicenseOps: assign and remove from free stock only

Status: **built** (two PowerShell levers, mock fixtures, notify templates, tests). Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-ONB-03`, `W-ONB-11`, `W-VND-02`. Controls: `C-05`, `C-06`, `C-32`, `C-35`. Depends on `B-28` (runner approvals), `B-16` (PowerShell bridge), `B-19` (family files). Standards: `STD-LV`, `STD-PS`, `STD-FX`.

## Why

New hires get licensed on day one without anyone spending the client's money, and licenses of people who left stop costing the client once their retention window is over. Buying seats stays with people (W-VND-02).

## Behaviour

- **`license.add`** (`Add-LicenseAssignment`, class write, `R1`, lead approval, technician executes, agent may dry-run). Params `upn`, `sku` (a SKU part number the client owns). A seat is free when `prepaidUnits.enabled` is more than the number of assignments of that SKU. With a free seat the diff is one `add` at `/licenses/<upn>/<sku>`. With none it returns `no free seat: a purchase needs the client's consent (W-VND-02)` and an empty diff. A user who already holds the SKU is an empty diff (convergent). An unknown user (also another client's user) or SKU is refused in the same way, with an empty diff.
- **`license.remove`** (`Remove-LicenseAssignment`, `R2`, `undo: license.add`). Same params. Allowed only when the assignment has a `retentionEndsOn` (the last day of the window) before the as-of date. The diff is one `remove` whose `before` holds the SKU and `retentionEndsOn`; the message repeats both. A window still open, or none recorded, is a refusal with an empty diff. No such assignment is an empty diff.
- **Refusals are data.** The PowerShell host reports a thrown error as its exception type name only (STD-ER-5), so the sentence a person must read cannot travel as an error. The function returns `data.outcome` (`assign`, `remove`, `unchanged`, `refused`) and `data.message`, with an empty diff, status `ok`. On an approved execute, an empty diff is audited as "no change: already in the desired state", and `data.message` says why.
- **No purchase.** No function that buys exists, and the manifest exports two functions. `governance/never-automate.json` already blocked `license.purchase*`, `order*`, `reduce*`, `cancel*`; this item adds `license.buy*`, `license.subscribe*`, `license.add-seat*`, `license.increase*` (outside `owns`, DECISIONS entry proposed). A lever with any of those names fails the whole load.
- **Data.** `fixtures/tenant/<client>/licenses.json`, a B-19 family file (`_meta.client` must match). `skus` imitate a Graph subscribedSku subset (`skuId`, `skuPartNumber`, `prepaidUnits.enabled`); `assignments` is a flat list this repo invented (`userPrincipalName`, `skuId`, `skuPartNumber`, `assignedOn`, `retentionEndsOn`). The Graph field names are **UNVERIFIED** here (written from memory, not read from Microsoft Learn this session); skuIds are invented and skuPartNumbers are modelled on real names. The module writes this file in execute mode in one atomic replace; the base tenant file is only read (to check the user exists).
- **Seeded stories.** Contoso: Premium 6 of 6 used (no free seat), one departed user whose window ended 2026-09-15; Essentials 2 of 4 used, one departed user whose window ends 2099-12-31 (synthetic far future so tests do not age). Fabrikam: Premium 6 of 10 with one window ended 2026-10-01; E3 3 of 3 used.
- **Notify.** `workflows/notify/templates/license.add.md` and `license.remove.md` (plain language: what changed, why, who approved, how to undo, who to call).

## Acceptance

- **B31-1** `license.add` (R1) succeeds in dry-run only when the SKU has a free seat; with none it returns `no free seat: a purchase needs the client's consent (W-VND-02)` and proposes nothing
- **B31-2** `license.remove` (R2) after the retention window only; the diff shows the SKU and the date the window ended
- **B31-3** no lever named license.purchase or similar can load (never-automate gate)

Tests: `tests/py/levers/test_b31_license.py`, named `test_b31_<k>_...`. The `pwsh` tests skip when PowerShell 7.4+ is missing.

## Known limits

- Mock only: no Entra or vendor portal is called. A real adapter needs license-assignment permission (not verified here) and a real seat read; the per-SKU free-seat arithmetic would then come from the vendor, not the fixture.
- The runner passes no as-of date to a PowerShell lever, so `license.remove` uses today in UTC. A dry-run just before midnight UTC and an execute just after could differ; the runner then reports "apply did not match the dry-run diff" and applies nothing more. `-AsOf` is honoured when a caller gives it (tested directly).
- Removing a license can affect data tied to it (for example a mailbox); the retention window is the client's choice and is recorded by the offboarding plan (B-36), not decided here.
- Only the total seat count is checked. Per-user SKU compatibility (for example two SKUs that overlap) is not modelled.
