# B-55 Data classes and the pre-prompt redaction gate

Status: **built** (data classes, shape rules, redaction gate inside the model gateway, fixture-based eval, tests). Offline; the hosted providers are still stubs. Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-GOV-01`, `W-SD-01`. Controls: `C-25` (data classification and pre-prompt redaction gate), `C-15` (loopback-only model gateway, hosted providers off), `C-27` (tenant isolation of prompts, context, logs and error text). Depends on `B-21` (the Phase 2 set and its `sensitive` labels). Standards: `STD-SC`, `STD-AU`, `STD-TS`. Decisions in force: D6-11 (model processing per client), D6-12 (client regimes and data floors).

## Why

A patient's name in a printer ticket never reaches a model it should not. The governance map (`docs/map/05-governance.md` section 3) defines seven data classes and three rules (unknown is high; the class of a text is the highest class of anything in it; the client's industry sets the floor). Until now nothing in code applied them: the gateway sent every text to whatever provider the route named.

## Behaviour

- **Data classes** (`core/guard/classify.py`). `DataClass.DC0` to `DC6` (an `IntEnum`, so `max` is the strictest), labels `DC-0` to `DC-6`.
- **Floor.** Text whose class the caller does not declare takes the floor of its client record's `industry` (`adapters.binding.ClientConfig`, D6-12): `dental` DC-4; `financial`, `ria`, `legal`, `accounting` DC-5; `other` DC-5. With no client record the floor is DC-5. The floor is read from the record, never from the text.
- **Shapes raise the class, nothing lowers it.** Secret shapes (private key headers, cloud and API key formats, JWTs, bearer tokens, connection-string passwords, client secrets, password disclosures, `otpauth://` seeds, BitLocker recovery keys, credentials inside a URL) are DC-6. SSN shapes and `00-nnnn-nnnn` account numbers (and cue-led account numbers) are DC-5; member ids after a `member` cue and dates of birth after `DOB` / `date of birth` / `born` are DC-4; names after a cue (`patient` DC-4; `investor`, `limited partner`, `<Name> Family Trust` DC-5; `client`, `the <Name> matter`, `named`, `the name`, an honorific DC-3), phone numbers and matter numbers are DC-3. A declared class (for example DC-0 for a public KB article) is used as the base, but any shape found still raises it.
- **Gate** (`core/guard/redact_prompt.py`). Text is normalised first (invisible characters removed, NFKC), so a zero-width character or fullwidth digits cannot hide a shape. DC-6 text is blocked and the gate returns no text at all. Otherwise each span becomes a typed, numbered placeholder (`[PATIENT_NAME_1]`, `[ACCOUNT_NUMBER_2]`); the same value gets the same number within one text. No mapping back to the values is kept.
- **Gateway** (`core/gateway/gateway.py`). `Gateway.complete(task, text, *, client=None, data_class=None)` runs the gate before anything else. Order: DC-6 blocked (no provider called, not even the mock); unrouted task; disabled provider; hosted provider (`azure_openai`, `anthropic`) with DC-4 or DC-5 text refused; then the provider receives the redacted text only. Every `Completion` carries `data_class` and `redacted` (the kinds replaced, never the values). Existing callers that pass no client get the DC-5 default floor, which the local mock and Ollama routes serve as before.
- **Eval** (`evals/redaction/report.py`, committed `report.md`). Leak rate of labelled PHI/NPI spans in the Phase 2 set, PII beside it, the miss list, spans redacted under another type, over-redactions, DC-6 false blocks, and the hosted and local route outcome for every ticket, using synthetic client records in `evals/redaction/clients/`.

## Acceptance

- **B55-1** every text passed to the gateway carries a data class (DC-0 to DC-6); unknown text takes the client's industry floor (dental DC-4; financial, legal and accounting DC-5) from the client record (D6-12)
- **B55-2** PHI- and NPI-shaped strings from the Phase 2 set are replaced by typed placeholders before any prompt; DC-6 shapes block the call
- **B55-3** redaction eval: leak rate on the synthetic PHI/NPI set reported fixture-based, with the miss list; the gateway refuses a hosted route for DC-4/DC-5 text

Tests: `tests/py/guard/test_b55_redaction.py` (`uv run --frozen pytest -p no:cacheprovider tests/py/guard`), functions named `test_b55_<k>_...`. Eval: `uv run --frozen python -m evals.redaction.report`.

## Known limits

- Shape rules are regular expressions written with the Phase 2 set in view (D-022); the eval's 0 leaks show the gate working on this set, not on real tickets. Names without a cue word are not found; the floor is what keeps such text off hosted models.
- Personal email addresses and street addresses are not redacted.
- The industry floor uses the client record's `industry` only. `model_processing` (D6-11) and `regimes` are not read by the gate yet; with no vendor register (`B-90`), DC-4/DC-5 are refused on every hosted route without exception.
- The real `config/clients/<id>.json` files are the owner step W2-E1, so the eval uses its own synthetic records. No caller passes `client=` yet. Triage and the other workflows still get the DC-5 default floor until they do.
- Placeholders cannot be turned back into values. A draft that needs the real name is completed by a person.
