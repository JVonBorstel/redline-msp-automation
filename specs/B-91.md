# B-91 Adapter contract tests and real-adapter stubs

Status: **built** (shared contract suite, closed real stubs, adapter reference page). The stubs are **stubs**: every call fails closed and no vendor client exists. Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-TOOL-11` (PSA, RMM and Graph integration maintenance). Controls: `C-02`, `C-27` (one client per unit of work). Depends on `B-18` (adapter base, bindings, PSA mock), `B-61` (RMM and Intune mocks), `B-68` (backup mock). Standards: `STD-TS`, `STD-DC`.

## Why

When the MSP's real PSA and RMM are known, plugging them in is a checked step: a real implementation goes into one registry and has to pass the same suite as the mocks before it can be selected.

## Deliverables

- `tests/py/contract/test_b91_adapters.py`: one table (`CASES`) of the six adapter interfaces (PSA, RMM, Intune, Graph, backup, alerts) and one set of rules run for every implementation, mock and real stub.
- `adapters/real.py` (**outside `owns`**, new file, nothing existing edited): `RealStub` and one closed stub per interface, plus `REAL_STUBS`, the registry the suite iterates.
- `docs/ADAPTERS.md`: per system the real API, least-privilege access, throttling (Graph 429 and `Retry-After`, cited), the GDAP role and SAM scope per Microsoft 365 lever, and what is UNVERIFIED.

## The contract (what every adapter must pass)

1. **One-client binding.** A binding of another client or another system is refused at construction (`AdapterError`) without naming the other client; `client` cannot be reassigned; a mock refuses another client's vendor id; a stub refuses the `mock` implementation and a mock refuses a non-mock one.
2. **Another client's object answers like a missing one.** For each lookup method the result for the other client's real id equals the result for an id nobody has (same `ok`, same words, no data). No result contains the other client's markers. Records of the other client filed inside this client's fixture (PSA, backup, alerts, RMM) are not served.
3. **Fail closed when unconfigured.** A stub answers every method, with any argument, `AdapterResult(False, "real adapter not configured", None)`. Every existing builder returns that for a non-mock binding and fails closed on a missing or broken client file.
4. **No secret in repr, results, errors or logs.** A stub refuses a credential *value* or another client's secret name at construction, without echoing it; it keeps the NAME only. Neither `repr`, `str`, any result reason, a crash reason nor the log (captured at DEBUG) contains a secret sentinel.
5. **Deterministic errors.** Same call, same result, on one instance and on two; reasons have no address, path, traceback or newline and stay short; a crash inside a call is `<Class> crashed: <ExceptionType>`, never the message; a caller mutating a result cannot change the next one; the mocks never touch their fixtures.

The table is checked against the interfaces: a public method added to an interface without a case fails the suite, and a registered stub without a case fails it too.

## Acceptance

- **B91-1** one contract suite per adapter interface runs against every implementation present (mocks today); a real implementation must pass it before it can be selected. Tests: `test_b91_1_*`, and every rule above is parametrized over mock and stub.
- **B91-2** `docs/ADAPTERS.md` lists for each system the real API, least-privilege scopes, throttling behaviour (Graph 429 and Retry-After, cited) and what is UNVERIFIED. Document check, no test.
- **B91-3** every adapter's real implementation selection fails closed when not configured. Tests: `test_b91_3_*`.
- **B91-4** `docs/ADAPTERS.md` names, per Microsoft 365 lever, the least-privileged GDAP role and the Secure Application Model delegated scope; app-only access is listed only for documented per-client app registrations (D6-09). Document check, no test.

Run: `uv run --frozen pytest -p no:cacheprovider tests/py/contract/test_b91_adapters.py`. Test functions are named `test_b91_<k>_...` for acceptance rules and `test_b91_<rule>_...` for the contract rules.

## Known limits

- **UNVERIFIED:** no real vendor API was called; every field name, GDAP role, SAM scope and throttle figure that is not sourced to a repo file is from memory (`docs/ADAPTERS.md`).
- A stub proves the closed door, not an open one. When a real client exists, rule 2 for it needs recorded vendor responses (403 versus 404 for another tenant's object); none exist.
- **Gap found, not fixed (outside `owns`):** `GraphMock` binds the tenant id only when the tenant fixture carries `_meta.tenantId`; the committed ones do not, so a Contoso adapter can be built with Fabrikam's tenant GUID and still serves Contoso data only (the user list is read from Contoso's own file). The suite skips that one check for Graph with an imperative `xfail` and says why.
- Backup and alerts have no builder, so their "selection" is the stub class; the builder tests cover PSA, Graph, Intune and RMM.
- Intune and Graph rows carry no owner field, so the poisoned-fixture test covers PSA, backup, alerts and RMM only.
- The suite reads committed fixtures (read only) and a handful of private copies under `tmp_path`; `config/clients/` does not exist in this tree (a protected owner step), so builder tests write their own client files.
