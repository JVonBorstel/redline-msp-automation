# B-33 MailboxOps and OneDrive transfer

Status: **built** (PowerShell module, registry fragment, notice templates, fixtures, tests). Synthetic data only. Every vendor field and cmdlet name is UNVERIFIED.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory (impact chains): `W-M365-01` (shared mailbox and distribution list changes), `W-M365-02` (Full Access and Send As grants), `W-M365-09` (mailbox size and archive), `W-ONB-09` (offboarding: mailbox conversion and auto-reply), `W-ONB-10` (offboarding: OneDrive transfer). Controls: `C-05` (dry-run by default), `C-06` (lead approval bound to lever, client and params), `C-35`, `C-25`. Depends on `B-28` (runner idempotency, per-client lock, R3 dual approval), `B-16` (Python bridge), `B-19` (per-client family files). Standards: `STD-LV`, `STD-PS`, `STD-FX`. Decisions: `D6-05` (R2 one approver, R3 two), `D6-07` (identity changes are R3), `D6-30` (module-qualified Verb-Noun names).

## Why

Joiners and leavers touch the mailbox many times a month by hand: add to a list, give a manager access, convert to shared, set an auto-reply. The pain named in the inventory is "manager gets full mailbox access without a business reason" and "access granted too broadly". The levers make each step one named, approved, audited change with a diff, an undo where one exists, and a plain notice to the affected person.

## Behaviour

- **Module** `levers/powershell/MailboxOps/` (`MailboxOps.psm1`, `.psd1`, `README.md`, `SOURCES.md`, `tests/`): twelve functions, each `[CmdletBinding(SupportsShouldProcess)]`, each returning `{ data, diff, applied }`. They read and write only `<tenant dir>/<client>/mailboxes.json` through JsonNode with one atomic replace. The client id is a slug before it is a path. No network, no credentials.
- **Registry** `levers/registry.d/mailbox.json`: twelve `runtime: "powershell"` write levers, all `R2`, `approval: lead`, agent dry-run, technician execute, `idempotency_keys` = all params. Undo pairs: add/remove list member, grant/revoke Full Access, grant/revoke Send As, set/clear auto-reply, grant/revoke OneDrive manager. No undo: `mailbox.convert-shared` (converting back needs a licence) and `mailbox.enable-archive` (switching off can delete mail).
- **Risk class.** The inventory rates all five items R2. A mailbox or OneDrive grant is data access, not an identity change (D6-07 covers credentials, MFA and contact details), so R2 with one lead approval stands; a client may raise `min_approvers` per lever. This is stated in the change note so a reviewer can overrule it.
- **Time-bound OneDrive grant.** `expires_on` (`YYYY-MM-DD`) is a required parameter, so the approval is bound to the exact date. The module refuses a date that is not after the as-of date or is more than 30 days away. Nothing expires the grant by itself; `mailbox.revoke-onedrive-manager` ends it and a person or scheduled job must run it.
- **Same-client guards.** A delegate or manager must be a user mailbox of the same client (not a shared mailbox, an outside address or the mailbox itself). Another client's person or list answers like an absent one.
- **Convert to shared** refuses a mailbox over 50 GB (the unlicensed shared mailbox limit is recalled from memory and UNVERIFIED; it is a guard, not a claim).
- **Auto-reply** text is validated by a registry pattern (letters, digits and basic punctuation, 5 to 400 characters, no markup, no links), because it is sent to outside senders.
- **Templates** `workflows/notify/templates/mailbox.<action>.md`, one per lever (the notify module looks for `templates/<lever>.md`; the lever names carry the `mailbox.` prefix).
- **Fixtures** `fixtures/tenant/<client>/mailboxes.json` for Contoso Dental and Fabrikam Capital: mailboxes, distribution lists and OneDrive access lists, pinned to `as_of` 2026-10-21. The loader's family rule (`_meta.client` equals the folder) applies.

## Out of scope

Reading mailbox state (no read lever; the audit `W-M365-05` and any size report are other items), forwarding, inbox rules, litigation hold and retention (never-automate list), licence removal (`W-ONB-11`), the choice of delegate (a person names it in the ticket; the approver reads it), and any scheduled job that ends a grant on its date.
