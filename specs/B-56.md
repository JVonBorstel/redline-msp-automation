# B-56 RAG ingestion with per-client namespaces and vault exclusion

Status: **built** (ingestion, namespaced in-memory store, deterministic embedder stand-in, tests). Offline: no model is downloaded or called, no network. Synthetic data only.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-KB-04` (cited question answering, the ingestion half), `W-KB-07` (credential vault entries: never ingested). Controls: `C-26`, `C-12`, `C-13`, `C-25` (pre-prompt redaction gate and data classes, B-55). Depends on `B-55` (`core/guard`: data classes, redaction gate) and `B-18` (per-client bindings; the client id is the job's, as in the adapters). The injection tripwire is `core/guard/detect.py`.

## Why

A technician asking "why does the front-office printer go offline?" should get Contoso Dental's article, never Fabrikam Capital's, and never a password. Retrieval (B-57) can only be as safe as the index it reads, so isolation, redaction and the vault rule are enforced at write time, in code, before anything is embedded.

## Behaviour

Package `rag/` (standard library plus this repo's `core`; a test checks the imports).

- **Job** (`rag.IngestJob(job_id, client, as_of, record=None)`). `client` is a client id, or `None` for the MSP's own documents. `as_of` is a `YYYY-MM-DD` date stamped into provenance; the clock is never read. `record` (optional `ClientRecord`) sets the data-class floor for undeclared text (D6-12); it must be the job's own client. A client id that is not a safe id, or is `msp-internal`, is refused (`IngestError`).
- **Namespaces** (`rag.store.models`). `client:<id>` holds one client's documents only. `msp-internal` is the single MSP namespace, for the MSP's own runbooks and templates. A client job writes to its client namespace and to nothing else; an MSP job (`client=None`) writes to `msp-internal` only. **The namespace is `job.namespace`**; a `Source` has no client field, text that says "this belongs to Fabrikam Capital" changes nothing, and the corpus loader refuses a manifest entry that carries a `client` key. A chunk id is derived from its namespace, so a chunk moved to another namespace no longer matches its id and the store refuses it.
- **Order per source** (`rag/ingest/pipeline.py`):
  1. Metadata (ids, origin, title, tags) must be safe and the text non-empty, else `invalid-source` / `empty-source`; a repeated `source_id` in one job is `duplicate-source-id`.
  2. **Vault exclusion.** A source whose tag or origin contains the whole word `vault`, `keyvault`, `credential(s)` or `secret(s)` is refused as `vault-source` before its text is read.
  3. **Redaction.** The B-55 gate runs on the title and on the text. A DC-6 shape (key, token, private key header, connection-string password, password disclosure, BitLocker key, credentials in a URL, and the rest of B-55's list) anywhere in either refuses the **whole source** as `secret-shape`. Otherwise every PHI, NPI and PII span becomes a typed placeholder (`[PATIENT_NAME_1]`) before chunking, so the tripwire, the embedder and the store only ever see redacted text. Text is normalised first (zero-width characters, fullwidth forms), so disguised shapes are still found.
  4. **Chunking.** Paragraphs are packed up to `max_chars` (default 600); longer paragraphs are cut at whitespace.
  5. **Injection tripwire and classification.** Each chunk, and each run of consecutive chunks short enough to hold one phrase, is scanned with `detect_injection`; the smallest tripping runs are flagged, so a phrase cut by a chunk boundary is still caught and clean neighbours are not. Rules the raw document trips that no run localised (hidden zero-width characters) flag every chunk of the document. The chunk's data class is the document's: the declared class, or the client floor, or DC-5 with no record, raised by any shape found.
  6. **Store.** A flagged chunk is stored as a record with its flag, rule ids, provenance and the SHA-256 of its text, but **empty text and no vector**, so it can never be retrieved or shown. Unflagged chunks are embedded and stored. Re-ingesting a source replaces all of its chunks atomically; a source that is now refused is removed from the index.
- **Provenance on every chunk** (`rag.Provenance`), withheld chunks included: `source_id`, `article_id` (what an answer cites), redacted `title`, `origin`, `job_id`, `as_of`, `doc_sha256` (of the redacted document), `chunk_index`, `chunk_count`, `char_start`/`char_end` (offsets into the redacted document), `embedder_id`, `pipeline` (`b56/1`).
- **Report** (`rag.IngestReport`). Per source: `indexed` or `refused` with a reason code, chunk counts, data class, redaction kinds, flag rule ids. It carries no document text and no matched value.
- **Store** (`rag.VectorStore`, `rag.InMemoryStore`). `search(vector, namespaces=[...], k=5)` looks only in the named namespaces; an empty list returns nothing, a malformed namespace (blank, wildcard, wrong shape) raises. Withheld chunks are never returned. Writes are validated before anything changes.
- **Embedders** (`rag.Embedder`: `id`, `dim`, `embed(texts)`). `rag.HashEmbedder(dim=64)` is a deterministic stand-in (signed blake2b feature hashing of word unigrams and bigrams, L2-normalised). Real embedders are adapters behind the interface and are off; none is included.
- **Corpus** (`fixtures/kb/<client-id or msp-internal>/manifest.json`, `rag.load_kb`). Synthetic: Contoso Dental, Fabrikam Capital and MSP-internal articles, including a PHI example, a planted injection, a document that claims to belong to another client, two vault-tagged entries, and one canary phrase per namespace. No fixture holds a secret-shaped value; DC-6 canaries are built at run time in the tests.

## Public interface for retrieval and evals

`rag.__all__`: `ingest`, `IngestJob`, `Source`, `IngestReport`, `SourceResult`, `IngestError`, `load_kb`, `KbScope`, `InMemoryStore`, `VectorStore`, `Hit`, `Chunk`, `Provenance`, `HashEmbedder`, `Embedder`, `client_namespace`, `MSP_INTERNAL`, `valid_namespace`, `PIPELINE_VERSION`, `DEFAULT_MAX_CHARS`. Retrieval embeds the question with the same embedder and calls `store.search(vector, namespaces=[client_namespace(caller), MSP_INTERNAL], k=...)`; each `Hit` carries the chunk, its provenance and a cosine score.

## Acceptance

- **B56-1** each client's documents go into that client's namespace plus one MSP-internal namespace; the namespace comes from the ingestion job's client, never from document text
- **B56-2** documents are scanned with the injection tripwire and classified before indexing; flagged passages are stored with the flag
- **B56-3** sources tagged as credential vault or containing DC-6 shapes are refused (W-KB-07), proven with canary secrets

Tests: `tests/py/rag/test_b56_ingest.py` (`uv run --frozen pytest -p no:cacheprovider tests/py/rag`), functions named `test_b56_<k>_...`.

## Interpretation notes

- **B56-1, "plus one MSP-internal namespace".** Read as: the set of namespaces is one per client plus one MSP-internal. Client documents are NOT copied into `msp-internal`: B-57 searches the caller's namespace and `msp-internal`, so a copy there would let client A's caller read client B's text. If the owner meant a copy, it needs a different retrieval rule first.
- **B56-2, "stored with the flag" versus withholding.** Both hold: the flagged chunk is stored (flag, rules, provenance, text hash) with no text and no vector, so it is auditable but never retrievable or quotable. A human finds the passage through the source and offsets.

## Known limits

- UNVERIFIED: nothing here was run against a real documentation platform export or a real embedding model. The source shape (`source_id`, `article_id`, tags, origin) is invented; the tag and origin words that mark a vault are a convention chosen here, not read from any vendor's data model.
- `HashEmbedder` is lexical, not semantic. It shares words or it does not match. Retrieval quality numbers built on it describe this stand-in only, not any real embedder.
- The injection tripwire and the DC-6 and PHI shape rules are B-55 / B-79 heuristics written for synthetic text. A missed injection is stored and retrievable (the lever registry's permission checks, not this index, are the control). Names without a cue word are not redacted (B-55 known limit). DC-6 shapes that B-55 does not know are not refused.
- Vault tag and origin matching fails closed: a harmless source tagged `secrets` is refused until a person re-tags it. A vault export that carries no vault tag and no secret-shaped text would be ingested; the control for that is how sources are selected for a job, which is not built.
- Redaction numbers placeholders per document, so one patient is `[PATIENT_NAME_1]` throughout a document but the same number in another document is a different person. The chunk data class is the whole document's, not per chunk.
- A document that trips a rule the scan cannot place (hidden characters) is withheld whole, which over-withholds by design.
- Ingestion writes no audit record; a refusal is visible only in the returned report. The store is in memory: nothing is persisted, and no real vector database adapter exists. No retrieval, citation, threshold or leakage eval (B-57).
- `max_chars` (600) is a plain default, not tuned.
