## Why

Recommendations are earned by evidence, not enthusiasm. A reader should be able to follow every line of the radar, the brief, the plan and the review method to a file or a test in this repo, and see at once what is mock and what nobody has verified.

## Behaviour

Pages: `governance/TECH_RADAR.md`, `docs/LEADERSHIP_BRIEF.md`, `docs/PLAN_30_60_90.md`, `docs/AUTOMATION_FRAMEWORK_REVIEW.md`. Code: `workflows/assurance/briefs.py`, wired into `python -m workflows.assurance` as `briefs check` and `briefs ranking [--write]`.

- **Citation rule.** Every table row (not header) and list item outside code fences cites at least one real file or folder in backticks, or a real test as `path::test_name` (the name must be defined in the file with `def`). A broken citation, a path that leaves the repo and an absolute path fail. A citation proves existence, not that the text says what the sentence says.
- **Radar.** One table: Area, Candidate, Ring, Evidence, Not shown. Ring is one of adopt, trial, assess, hold. Every row has evidence and a non-empty Not shown cell. An `adopt` row must cite an eval report or test (`evals/` or `tests/py/`). Candidates with no code and no eval in the repo (OpenTelemetry, pgvector, Qdrant) are not adopted, and the hosted adapters are held. Every candidate of the planned stub stays on the radar.
- **Leadership brief.** The ranking table between the `ranking` markers is generated from the ten intake scores (`score_examples`): rank, risk class, assumed hours, fixture acceptance, priority and verdict, with a source cell citing the intake file and the eval report. Blocked, unmeasured and design-review ideas get no rank. `briefs check` fails when the committed table differs from the generated one; `briefs ranking --write` refreshes it.
- **Framework review.** A checklist of five questions (rights, secrets, idempotency, logging, owner), a verdict mapping, an automation-fit table by kind of work, and a blank review record in a code fence. It cites Q-07 and D6-26 and states that it makes no claim about any real script; the checker fails on a script file extension outside code spans.
- **Plan.** Three windows (days 1 to 30, 31 to 60, 61 to 90), each ending in an exit check; every `B-nn` mentioned must exist in `map/roadmap.json`; it is labelled a proposal with no dates.
- **All pages.** The prototype label, the word fixture-based, an UNVERIFIED marker and a Not shown, Unverified or Limits section; no money figure, no promise word, no promised result or percentage, no claim of proof or production use.

## Known limits

- The checker finds missing and broken citations. It cannot tell whether a cited file supports the sentence; a person reads the pages.
- The rings are judgements from thin, fixture-based evidence: mock model tiers, author-written gold labels, a hand-written injection corpus. They do not rank products.
- The radar is not the vendor register of `C-43`, which stays planned.
- No existing script was reviewed (Q-07); the method has never been applied.
- The plan was not checked against any real workload or staffing; the owner-only steps depend on the owner.
- The facts about the build machine come from the 2026-10-09 environment audit and were not re-run.
- Run on Windows with uv's managed Python; not run on Linux.
