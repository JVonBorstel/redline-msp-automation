# B-80 Gateway budgets, circuit breaker and model-call audit

Status: **built** (budgets, breaker, audit record, config, tests) on mock and test-double backends. Per-process, in-memory counters only. Nothing here calls a real provider.

> Independently built prototype. Not affiliated with any vendor's or real company's systems. Synthetic data only.

Inventory: `W-TOOL-02`, `W-TOOL-09`. Controls: `C-17`, `C-32`, `C-40`, `C-11` (never-log list). Standards: `STD-AU`, `STD-ER`, `STD-CF`. Drift item closed: `DR-17`. Depends on `B-17` (audit record v2: the `model.complete` event and `request_id` exist, nothing wrote them until now).

## Why

A loop in a workflow, a runaway agent or a provider outage must not run up cost or hide behind silence. Today the gateway (D-018) will call a provider as often as it is asked, keeps hammering one that is down, and leaves no record that a model was ever called. For Contoso Dental's help desk, that means one stuck triage loop could spend the whole day's local-model capacity before anyone notices, and an auditor asking "what did the agents send to a model last Tuesday?" gets nothing. B-80 adds three things inside the gateway, where a fooled caller cannot skip them: budgets, a breaker, and a metadata-only audit record per call.

## Behaviour

### Budgets (B80-1)

- Limits come from `config/limits.json` (below). Three scopes are tracked for every call: **global**, **client** and **agent**. Each scope may have a `Budget` of `max_calls` and `max_tokens` per window; an absent number is not limited.
- A call is admitted only if **every** scope has room. It is then charged to all three at once under one lock, so a call refused by one scope costs the others nothing, and N threads cannot all squeeze through the last slot.
- Over budget returns `Completion(ok=False, error="budget exceeded")` with empty text. The provider is never called. Which scope and dimension said no goes in the audit record (`result.reason`: `budget:global:calls`, `budget:client:tokens`, `budget:agent:calls`, ...), not in the caller-facing text.
- Client and agent: `per_client` and `per_agent` each hold a `default` budget (applied to every id) and `overrides` (by id, replacing the default for that id). A call with no `client` or no `agent` is counted under the id `unattributed` and meets the default budget, so leaving the name off does not escape the limit.
- **Tokens are estimates**: `ceil(characters / chars_per_token)`, `chars_per_token` from config (default 4). No provider in this repo reports real usage. The prompt estimate (of the text actually sent, after redaction) is checked and charged before the call; the completion estimate is charged after, so one call can overshoot a token budget by one completion and the next call is then refused.
- **Window**: the window opens at the first call after a reset and lasts `window_s` seconds of the injected clock; then every counter returns to zero. It is a fixed window, not a sliding one: a burst at the end of one window and the start of the next can reach twice the limit.
- What is charged: every call that reaches the provider (including one that fails, because the backend may have done the work). What is not charged: calls refused before the provider (blocked DC-6 text, no route, provider disabled, hosted refusal, open breaker, over budget).
- Without a `limits` section (a `GatewayConfig` built in memory, or a root with no `config/limits.json`) there are no budgets and no breaker, exactly as before B-80.

### Circuit breaker (B80-2)

- One breaker per provider, so a dead Ollama does not stop the mock. Settings from `limits.breaker`: `failure_threshold` (N) and `open_s` (T).
- **Closed**: calls go through; N consecutive `ProviderError`s open it (a success resets the count).
- **Open**: every call fails fast with `Completion(ok=False, error="circuit open: provider '<name>' is failing; calls fail fast until it recovers")`. The provider is not called and no budget is charged.
- **Half-open**: once T seconds have passed on the clock, exactly one probe call is let through. Success closes the breaker; failure re-opens it for another T seconds. Other callers during the probe fail fast. A probe slot is handed back if the call is then refused by a budget.
- An unexpected exception from an adapter (not a `ProviderError`) also counts as a failure, is audited, and is then re-raised unchanged: a bug is not hidden as a provider outage.
- The clock is injected: `Gateway(config, clock=...)`, a callable returning seconds (default `time.monotonic`). The tests move a fake clock by hand; nothing sleeps.

### Model-call audit (B80-3, DR-17)

- `Gateway(config, audit=<sink>)` takes anything shaped like `AuditLog.append`: an `AuditLog`, or an `AuditRouter` (B-42) that keeps one chain per client. With no sink, nothing is written and results are unchanged.
- Every call, allowed, denied or failed, appends one v2 record: `event: "model.complete"`, `lever: "model.complete"`, `mode: "execute"`, `agent` (the caller's, else `unattributed`), `client` (id or null), `actor_kind` and `request_id` as the caller passed them (else the audit defaults `unknown` and a fresh `req-<uuid>`), `lever_version` null.
- `params`: `provider`, `model` (null when none was routed), `task`, `prompt_sha256`, `input_chars`, `prompt_chars`, `data_class` (label), `redacted_kinds`.
- `result`: `status` (`ok`, `denied` or `error`, STD-ER-2), `ok`, `reason` (a fixed code: `ok`, `blocked`, `no-route`, `provider-disabled`, `hosted-refused`, `circuit-open`, `budget:<scope>:<dimension>`, `provider-error`, `crashed`), `latency_ms`, `completion_chars`, `prompt_est`, `completion_est`.
- **Never written**: the prompt, the completion, a provider's error message (it may echo a URL or input), or any PHI/PII/secret value. `prompt_sha256` is the hash of the text the model was **sent**, after the B-55 redaction gate, so a Social Security number in a ticket is neither in the log nor guessable from it. For DC-6 (secret-shaped) text nothing is sent and no hash is written (`null`). `input_chars` is the caller's text length, `prompt_chars` the sent text's.
- The hash is written as eight space-separated groups of eight hex digits (the same form as B-49), because the audit redactor blanks any run of 32 or more hex digits (STD-AU-5). Field names avoid `token`, `key`, `secret` and `password` for the same reason (hence `prompt_est`, not `prompt_tokens`). A test asserts no field is blanked.
- **Fail closed**: if the record cannot be written (head pin mismatch, locked or unwritable log), a successful completion is withheld: `Completion(ok=False, error="audit unavailable: ...")`. A call that was already denied or failed is returned as it was.
- Time-of-call (`ts`) is the audit module's own UTC clock; only budget windows, breaker timing and latency use the injected clock.

### Config (`config/limits.json`, STD-CF)

```json
{ "version": 1, "window_s": 3600, "chars_per_token": 4,
  "global": { "max_calls": 2000, "max_tokens": 2000000 },
  "per_client": { "default": { "max_calls": 500, "max_tokens": 500000 }, "overrides": {} },
  "per_agent":  { "default": { "max_calls": 300, "max_tokens": 300000 }, "overrides": {} },
  "breaker": { "failure_threshold": 5, "open_s": 30 } }
```

- Validated by pydantic models with `extra="forbid"` (`LimitsConfig` in `core/gateway/config.py`); a limit of 0, a negative number, a boolean, an unknown key or an override that sets no limit is refused. `version` must be the integer 1.
- `GatewayConfig.load` reads the file when it exists. A missing file means no limits (older roots and test trees still load). This is a deliberate exception to STD-CF-3 so existing callers keep working; the committed file is present and a present file must be valid. The numbers are prototype defaults, not measured.

## Acceptance

- **B80-1** per-client and global budgets (calls, tokens) from config; over budget returns `Completion(ok=False, error="budget exceeded")`. Per-agent budgets are added on the same mechanism.
- **B80-2** a provider failing N times opens a breaker for T seconds; calls fail fast and recover after T.
- **B80-3** each call writes a `model.complete` v2 audit record with provider, model, task, prompt SHA-256, lengths, latency and ok, and no prompt or completion text (DR-17).

Tests: `tests/py/gateway/test_b80_budgets.py` (`uv run --frozen pytest -p no:cacheprovider tests/py/gateway`), functions named `test_b80_<k>_...`. Written failing first (the first run was an import error: no `BudgetTracker`, no `limits`). They use provider doubles and a fake clock; no network, no sleeps.

## Known limits

- Counters live in the process. A restart resets budgets and breaker state, and two processes (the web page and a CLI) each have their own. A shared, persisted ledger is not built; until it is, the budgets limit a runaway loop inside one process, not total spend across processes.
- Token counts are character-based estimates. The real tokenizer of a real model will differ, more for non-English text and code.
- Fixed window (see above), and one global breaker setting for all providers.
- The `ts` of an audit record is wall-clock UTC and not injectable, so record bytes differ between runs; the tests assert structure, not bytes.
- Callers do not pass `agent` yet (triage, replies and the other workflows call `complete` without it), so their calls count under `unattributed` and the default per-agent budget is shared by all of them. Passing the real agent id and `actor_kind` is a small change in each workflow, not done here (outside `owns`).
- `python -m core.gateway` builds a fresh gateway per call, so budgets and the breaker do not persist across CLI invocations, and it passes no audit sink.
- Hosted providers are still stubs (D-018); the breaker and budgets apply to them but nothing real runs behind them.

## Not in this item

- A persisted or cross-process budget ledger; per-task or per-model budgets; cost in money (no prices are known here).
- Alerting when a breaker opens or a budget is nearly used up (the audit records are the evidence; nothing watches them).
- Wiring `agent`, `actor_kind` and `request_id` from the runner, queue and workflows into their `complete` calls.
