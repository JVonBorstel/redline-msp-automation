## What it does

After a lead approves a proposal and the runner executes it, a technician runs:

    uv run --frozen python -m workflows.notify <proposal-id> --state <dir>

It reads the proposal from `<dir>/queue.jsonl` (read only; the queue is never written), fills the lever's template `workflows/notify/templates/<lever>.md` from trusted fields only, and writes the draft to `<dir>/notices/<proposal-id>.md` (and prints it). A person reads it, edits it if needed and sends it.

Trusted fields used (STD-LV-9; no ticket subject or body, no model):

| Placeholder | From |
|---|---|
| `$first_name` | `displayName` of the user named by the proposal's `upn` in the state folder's mock tenant (first word), else "there" |
| `$request` | the proposal `source` and `ref`; for a triage ticket, whether the ticket's `requester` form field equals its `affected_user` ("your request" or "a request from your workplace") |
| `$approver` | `decided_by` identity's display name before the bracket, from `config/identities.json` |
| `$team`, `$fast_phone`, `$hours` | `fixtures/notify/contacts.json` entry for the proposal's client (fail closed when missing) |

Each value must be one line without `$`, `{`, `}`, `<` or `>`; anything else fails the draft (no partial draft is written).

## Acceptance

- **B04-1** `python -m workflows.notify <proposal-id> --state <dir>` writes `<dir>/notices/<proposal-id>.md` for an `executed` proposal and exits 0. A proposal that is `pending`, `approved`, `rejected` or `failed` is refused with exit 1, a reason that names the status and says no draft was written, and no file is created. An unknown proposal id, a missing queue file or a bad id shape exits 2.
- **B04-2** Every write lever in `levers/registry.json` has `workflows/notify/templates/<lever>.md`; the test fails naming the lever when one is missing, and drafting for that lever fails closed. Filling is deterministic (same inputs give byte-identical drafts) and uses no model (the package imports nothing from `core.gateway`). A template placeholder with no trusted value fails the draft.
- **B04-3** The T-3101 draft (Priya Nair, `user.reset-mfa`, contoso-dental, approved by `lead-lee`) says what changed, why (ticket T-3101), who approved it (Lee), how to get back (the fast-path number from `fixtures/notify/contacts.json`, in the 555-01xx range) and how to undo it. It contains no secret-shaped value (the audit redactor leaves it unchanged), no phone number other than the client's fast-path number (none from the tenant), at most 120 words, and a Flesch-Kincaid grade of 8 or lower computed in the test. The same checks hold for a `user.disable` draft, and a contoso draft never shows the fabrikam number (isolation).
- **B04-4** The first line of every draft is exactly `Draft. A person reviews and sends this.` (HO-9).
