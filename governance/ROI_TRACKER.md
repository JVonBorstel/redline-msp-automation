This page is generated by `uv run --frozen python -m workflows.assurance generate --write` from `governance/roi_fixtures.json`, `governance/intake_rubric.json` and the committed eval reports. Do not edit it by hand; `check` fails when it drifts.

**Every number below is fixture-based.** The acceptance column is a count read from an eval report whose gold labels, fixtures and rules were written by one author, with mock providers. Minutes per run, runs per month and build effort are invented placeholders (assumed), not the MSP figures. **Not a saving**: the hours column is assumed hours multiplied by a fixture rate; it shows the method, not money or time saved at any client.

## Method

`priority = (assumed hours per month x fixture acceptance) / (assumed effort in days x risk weight)`, rounded to two places. Hours per month = assumed minutes per run x assumed runs per month / 60. Risk weight by class: R0 = 1, R1 = 2, R2 = 4, R3 = 8 (proposals; `governance/intake_rubric.json`). The same function scores an intake (`governance/USE_CASE_INTAKE.md`).

## Limits

- Acceptance here is the share of fixture cases an automation got right against author-written gold labels. It is not the share of drafts a technician would accept unedited; no technician has used any of these.
- Every automation in the table is read-only or draft-only (R0), so the risk weight does not separate them.
- Rows are ranked by the formula only; nothing about build order, staffing or value to a real client follows.
- Replace the assumed columns with the MSP's own measurements before showing any figure as a result.
