## Why

A stolen laptop is contained fast and nobody wipes the wrong device (W-EP-08, W-ONB-12, W-SEC-05; C-05, C-06, C-07, C-29, C-30, C-32).

## Individual to macro (L1-L4)

- L1: Ana at Contoso Dental has a lost laptop locked in minutes; the approver sees that locking the front-desk PC would stop check-in before approving.
- L2: Contoso Dental's devices are only touched by leads scoped to it, one device per approval, owner must match.
- L3: the MSP gets two-lead, verified, audited device containment instead of calls nobody records.
- L4: fast containment limits breach risk at every client; no bulk path exists.

## Honest limits

- Everything is a mock. Intune, Defender and Datto RMM names, endpoints, permissions and behaviour are UNVERIFIED (`SOURCES.md`). Wipe only records a request.
- When this item merged, the approval queue and page sent one approval to a runner without a policy and could not collect the second lead or the contact confirmation. **Since closed** by `docs/changes/B-28-dual-approval.md` (D-067): the page collects the callback source and the authorized contact, and a second, different lead completes the approval.
- A named `window_override` on an approval lifts the business-hours window for any lever, wipe and retire included (runner rule B42-4, unchanged). So "after hours refused unless the client record allows it" holds unless a lead records an override; the audit keeps the name. Proposed: a lever flag that forbids override for irreversible levers.
- No registry `caps`: an existing B-42 test requires every other write lever to use the risk-class default, so R3 default caps apply (targets per run 5, 10 per hour, 10 clients per day). One device per call comes from the single-uid `device` param, not from caps.
- Lock, retire, wipe use `requester+contact`, which refuses a device whose owner holds a directory role (D6-06): a lost admin laptop needs the human procedure. Isolate and release use `requester` only.
- Through the lever host every PowerShell refusal reads `crashed: RuntimeException`; the legal-hold reason is not visible in the audit.
- `legalHold`, `role`, `onlyDeviceForRole` and `holdsRegulatedData` are invented device fields; a real build reads hold status from client records.
- Notice drafts need the queue path; not exercised here beyond template placeholder checks.
- Not run: Pester (module tests are plain scripts), any real pwsh on another OS.

## DECISIONS proposal

D-0xx Retire is irreversible (B-65, 2026-10-27). `device.retire` is registered `irreversible`: the runner then demands approvals under 24 hours old and never applies pre-authorized containment. Wipe request is recorded by the lever and started by a person (D6-08). Unlock is R2, release is R3. Why: removed company data cannot be put back; W-ONB-12. Alternative: retire as reversible with a re-enrol undo (rejected: data is not restored). What would change it: the MSP's real retire semantics.
