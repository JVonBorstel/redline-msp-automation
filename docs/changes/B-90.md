## Why

A hosted model is where client text leaves the machine. "Someone set `enabled: true`" is not a recorded decision. Now a hosted call needs an approved, in-date register entry that names the provider, the client, the data class and the purpose, and a client record that says `model_processing: hosted`; anything else is refused, audited with a fixed code, and nothing is sent.

## Individual to macro (L1-L4)

- L1: Ana, a technician, asks for a ticket summary for Contoso Dental; with no approval she gets a plain refusal and the local model path still works.
- L2: Contoso Dental's text only ever goes to a hosted model if its own id is in an approved entry and its record says `hosted`; another client's approval does not cover it.
- L3: the MSP has one file that shows what is approved, until when, by whom; every refusal and every allowed hosted call has an audit record with the approval id and purpose.
- L4: a hosted model cannot become the quiet default; adding one is a written, reviewed, dated decision.

## Honest limits

See `specs/B-90.md`. Main ones: nothing ran against Azure and the request/reply shapes are UNVERIFIED; the roadmap's "fake server on 127.0.0.1" is replaced by an injected in-process transport because the adapter has no HTTP client; a declared data class is trusted for shapeless prose (documented by a test); Key Vault resolution is not built; the committed config still names no approval, so hosted stays off.

## DECISIONS proposal

D-0xx Hosted routes need a recorded approval, checked in code (B-90, 2026-10-27). `governance/ai-vendor-register.json` is the only approval; an entry names provider, clients, data classes, purposes, retention terms, approver, date, and a review date after which it stops approving. The gateway checks it on every hosted call after redaction; a missing register, a missing field in a client record, or an expired entry all refuse. Secrets in config are references (`env:`/`keyvault:`), never values. Why: D-018, D6-11; C-15, C-25, C-28, C-43. Alternative: a boolean per provider in config (rejected: no who/for-whom/until-when). What would change it: the MSP's actual approval and review process (B-93).
