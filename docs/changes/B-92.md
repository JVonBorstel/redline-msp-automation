One short policy staff can actually follow. B-55 put the data classes into code; this gives technicians the same rules in plain words, and a test fails if the words and the code or map drift apart.

## Honest limits

- "Two pages" is measured as at most 1,200 words and 120 source lines, not a rendered PDF.
- The DLP index column is not in `docs/map/05-governance.md` section 1. It is labelled as derived (from `ISO-2`, `ARC-12` and rule 1). No retrieval index exists yet, so nothing enforces it.
- The hosted conditions for DC-1 to DC-3 are rules for people: the gateway would send redacted DC-0 to DC-3 text to a hosted route if one were enabled. Today both hosted providers are disabled in `config/models.json` and are stubs. `C-28` (approval gate) is planned.
- The audit-log column is enforced for secrets only (`core/audit/redact.py`). No scanner rejects PHI or NPI in audit params.
- D6-19 (consumer access decisions stay human) is a written rule; `governance/never-automate.json` has no pattern for it. Changing that file needs a decision record and is outside this item.
- `core/guard/classify.py` says the data classes are in governance map "section 3"; they are in section 1. Not changed here (outside `owns`).
- UNVERIFIED (policy section 7): the six-month review cycle, the consequence for breaking the policy, regulation applicability, and the Colorado AI Act scope; counsel confirms.
- Who holds the compliance owner and AI change approver roles is unknown (D6-17).
