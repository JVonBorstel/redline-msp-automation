## Why

A client owner sees, in plain words, what is healthy and what is not, and every number in it is checked against its source before the draft exists (SOC 2 evidence for C-21, C-27).

## Individual to macro (L1-L4)

- L1: a practice manager at Contoso Dental reads one page that says 2 backup jobs failed and 3 devices wait for a critical update, instead of asking.
- L2: each client's report contains that client only; the isolation test searches for every other client's name and ticket ids.
- L3: the MSP lead reviews a draft per client that already reconciles with its sources, and a later QBR or digest can call `build_report` instead of re-reading fixtures.
- L4: smaller clients get the same plain-English health view as larger ones.

## Honest limits

- Fixture shapes for patching, awareness and baseline drift are this repo's own and UNVERIFIED against any vendor; the phishing-simulation and vault vendors are UNVERIFIED (U-04). Those figures are service-level, not per person.
- October ticket figures cover to 2026-10-16 only (the ticket set's date). Thresholds are stand-ins.
- The accepted-rephrase path is proven with a model double; the default mock gateway's canned text is rejected and the computed summary stays. No real model was called.
- Draft only: no approve, send or schedule step exists. Litware Legal has no backup fixture and shows that as a gap.

## DECISIONS proposal

D-0xx The client health report is reconciled after rendering and drafted only (B-71, 2026-10-27). The validator reads the finished HTML and the raw source files and recomputes every figure with separate code; a mismatch writes nothing. A model rephrase is accepted only when it keeps every fact phrase and exactly the computed figures, then the whole page is validated again; otherwise the computed text stays. The report is a draft with no reviewer and the package has no send path. Why: W-RPT-01, W-SEC-10; C-21, C-27, C-41. Alternatives: letting the model write the summary freely (rejected: a changed number would reach a client), one MSP-wide report (rejected: crosses clients). What would change it: the MSP's real report format and review step.
