# B-42 change note: blast-radius caps, per-client audit chains, windows, pre-authorized containment

Status: **built** against the **mock** tenant. Synthetic data only. Spec: `specs/B-42.md`. Tests run on 2026-10-23 (Windows, before the PR): Phase 0 602 passed, Phase 1 385 passed, demo smoke 32 passed, all of `tests/py` passed (in two runs); CI on the PR is the final check.

- `core/audit/router.py` (new): `AuditRouter` (a chain per client plus `_msp`), `file_lock` (cross-process, fails closed), `valid_client_id`; the OS lock code moved here from `core/queue/store.py`, which imports it back.
- `core/levers/caps.py` (new): `DEFAULT_CAPS`, `caps_for`, `CapLedger`, `ClientRules` and `Window` (business hours, maintenance window, time zone), `SecondReviewStore` and `Review`.

- `core/levers/runner.py`: window and cap checks inside the per-client lock; the containment path; `check_reviews`, `complete_review`; the replay guard reads only the client's chain; the audit may be a router or a plain log.
- `core/levers/__main__.py`: the CLI builds the router; new `verify`, `export`, `reviews`, `complete-review`, and `--clients`, `--demo`, `--on-call`, `--window-override`.
- `core/queue/store.py`: `open_queue` builds the router at `<state>/audit/`. `ui/app.py`: chain picker, per-chain verify, dry-run diff read from the client's chain, overdue-review banner.

- `tests/py/levers/test_b42_caps.py` (new), `specs/B-42.md` (new).

## Why

One runaway or one mistake must not spread across 300 tenants. Caps bound what a lever can do per hour and per day, a chain per client makes evidence exportable per client, windows keep risky changes inside agreed hours, and pre-authorized containment lets one on-call lead stop a compromise with a second look due the next business day.

## Individual to macro (L1 to L4)

- **L1, one person.** A compromised account is disabled or signed out on one on-call approval instead of waiting for a second lead, and a wrong target is limited to one person per run. A change that should not land at 3 a.m. on a person's workday is held until the agreed hours.
- **L2, the client business.** The client chooses its business hours, maintenance window and whether containment may go on one approval. A client with no window gets no after-hours changes. Its audit chain can be handed to its auditor alone, with no other client in it (HIPAA business associate, Safeguards service provider evidence).
- **L3, the MSP.** A runaway script or a mistaken bulk run stops at the cap, is audited, and cannot cross into 300 tenants. Pre-authorized actions leave a second review with a due date; a missed one is audited and shown on the page. The UI and the CLI write through one locked path, so the SOC 2 evidence is one consistent set of per-client chains.
- **L4, community.** Faster containment at every client limits how far one stolen sign-in travels, and per-client evidence makes it practical for small clients to be audited at all.

## Gaps, named (nothing worked around)

1. **Existing tests and docs that read the single log were moved to the client chain (repair round 1).** `open_queue` and the CLI now write `<state>/audit/<client>.jsonl`, as B42-2 and B42-3 require. Outside the item's own files, only the audit path (and, where one chain became several, the expected count or seq) was changed: `tests/demo/test_b10_demo_smoke.py` (the first dry-run seqs are now 1 and 2 for Contoso, 1 for Fabrikam), `tests/phase1/test_levers.py`, `tests/phase1/test_ui.py`, `tests/py/audit/test_b17_audit_v2.py`, `tests/py/docs/test_b11_trace.py`, `tests/py/levers/test_b02_runner_gates.py`, `tests/py/queue/test_b03_approval_page.py` (the tamper test now sees Contoso's 2 records, not 3), `tests/py/rollback/test_b41_rollback.py`; and the commands in `docs/DEMO.md`, `docs/TRACE_T3101.md`, `README.md`. No assertion was removed or loosened. All of these pass (2026-10-23).
1a. **Rollback CLI needs `--client`.** `workflows/rollback/__main__.py` read `queue.runner.audit.path`, which is now the MSP chain; an audit seq is only unique inside one chain, so `--client` is required. `workflows/triage/__main__.py` prints the client chain path. `ui/app.py` opens the audit page on the first client chain (the MSP chain only when there is no client chain).
1b. **`preauthorized_containment` on an irreversible lever loads.** An existing B-01 test makes `user.disable` irreversible and expects the registry to load, so the model no longer refuses the combination; the runner refuses the path in code and says so.
2. **Audit events.** `core/audit/chain.py` is not owned, so review and cap records use existing `event`/`mode` values with the meaning in `result.kind`. A later item should add a `review.*` event.
3. **Client schema.** `schemas/client.schema.json` is closed and not owned; the four new client keys are parsed in `caps.py` and a real client file carrying them fails that schema until it is extended.
4. **Time zones.** `tzdata` is not in `uv.lock` and `pyproject.toml` is not owned. A fixed `UTC±HH:MM` always works; an IANA name works only if the machine resolves it, otherwise the window is refused with a plain reason. On the Windows build box they do not: `ZoneInfo("America/Denver")` raises `ZoneInfoNotFoundError: No module named tzdata` (2026-10-23), so only `UTC±HH:MM` works there today. The owner of `pyproject.toml` should add `tzdata`.
5. **Other write levers have no explicit caps.** Mailbox, group, license, credential and the rest are other items' files; they use the risk-class default, and a test lists them.
6. **No lever carries `window` yet, and there is no device-isolate lever.** The mechanisms are registry-driven and proved with synthetic levers; flagging a real lever or adding device isolate needs no runner change.
7. **Alerts** are an audit record, a page banner and a non-zero CLI exit. The outward channel (`workflows/notify`, `adapters/alerts`) is not in this item.
8. **Holidays** are not modelled in "next business day".
9. **Targets per run** is exercised on the ledger directly, because lever parameters cannot be lists yet.
10. **Cross-process cap race.** The cap check is atomic per client inside one process only; see `specs/B-42.md`.
11. **No migration.** Old `<state>/audit.jsonl` files are neither read nor moved.

## DECISIONS proposal

D-0xx Default caps by risk class and the second-review store (B-42, W4). A write lever without registry `caps` gets R1 25/60/50, R2 10/30/25, R3 5/10/10 (targets per run / executes per client per hour / clients per day), so a new lever is never uncapped. A pre-authorized containment writes a second-review item to `_reviews.jsonl` beside the audit chains, due at the end of business hours on the next business day. Why: HO-6 and D6-08 need a number and a due date; these are starting points for the owner to tune, not measured values. Alternative: fail the registry load for a write lever without caps, which forces every family to pick numbers now. What would change it: real volumes from a pilot, or a decision to require explicit caps.
