## Why

Mac and Linux users get the same safe automation as Windows users. An agent can only press a button: the registry names a vetted script, the bridge checks its hash, passes the parameters as data and kills it at the timeout, and the runner makes a write lever's real change match its dry-run diff exactly.

## Individual to macro (L1-L4)

- L1: a hygienist at Contoso Dental whose Mac is out of disk space or whose printing service stalled gets it fixed by an approved, listed action rather than waiting for a visit.
- L2: the client's change is a named file list or a named service from a fixed list, in the client's own host state only; one client's host is never read or changed for another.
- L3: the MSP can show an auditor the dry-run diff, the lead's approval and the audit record for every Mac or Linux action, and a script edited without a manifest change cannot run.
- L4: Mac and Linux fleets get the same guarantees as Windows ones, and no free-form shell exists for a fooled model to reach.

## Honest limits and unverified

- Mock only: no `systemctl`, `launchctl` or real file system layout is used or verified. The service names (`cups`, `chronyd`, `rsyslog`) and cache scopes are invented for the mock.
- Run only on Git Bash on Windows (MSYS2 bash). Not run on Linux, on macOS, or on bash 3.2. `shellcheck` is not installed here, so the lint test is skipped, not passed.
- The request has no `entry` object (the committed request schema requires a PowerShell one); see `specs/B-66.md`.
- The hash pin and the allowlist are in the same repository as the scripts; review of the manifest change is the control.
- `clear-cache` is registered `reversible` on a judgement that cache files are disposable.

## DECISIONS proposal

D-0xx Bash levers share the PowerShell bridge's guarantees (B-66, 2026-10-27). A lever with `runtime: "bash"` names a bare script listed with its SHA-256 in `levers/bash/manifest.json`; the bridge copies the verified bytes to a private folder, runs `bash --noprofile --norc` with a scrubbed environment and a hard timeout, passes parameters only as a JSON line on stdin limited to `[A-Za-z0-9._:@+-]`, and the runner requires the real change to equal the `--what-if` diff. Parameters of a bash lever must be enums or tight patterns, and command-like names are refused at load. Why: W-EP-09; C-05, C-17, C-01. Alternative: reuse PowerShell Core on Mac and Linux (rejected: a second runtime on every Mac and Linux host to install and patch; the roadmap asks for bash). What would change it: the MSP's real fleet mix, or a decision to require PowerShell 7 everywhere.
