## Why

Clients should stop paying for seats nobody uses, with proof. Billing today pulls counts from three systems and reconciles by hand. This does the comparison for one client, shows the arithmetic, and turns each difference into a proposal that needs approval.

## Individual to macro (L1-L4)

- L1: Ana, a technician, sees on one page which Contoso Dental seats are unused, orphaned or duplicated and which subscriptions and warranties end soon, instead of exporting three systems into a spreadsheet.
- L2: the report for Contoso Dental carries only Contoso Dental rows; another client's device or ticket row in a shared fixture is dropped and a mismatched file is refused.
- L3: every number is re-added by the report itself and by a test; every proposed change names its evidence, its approver role, and says it has not been executed. Spending stays a human act (W-VND-02).
- L4: fewer seats paid for and not used, fewer lapsed renewals, fewer billing disputes, on the day a real run replaces the fixtures.

## Honest limits

See `specs/B-75.md` Known limits. In short: no vendor portal, billing system or live API was used; the billing model, overlap rule, prices, renewal and hardware dates are invented; the sign-in fixtures are a sample, so "unused" is overstated; contract minimums are not modelled; only two clients have inputs; the run is a file with a hash, not an audited lever call and has no requester identity; approvals are not recorded here.

## DECISIONS proposal

D-0xx Licence true-up is a read-only report of proposals (B-75, 2026-10-27). One client per run reads existing licence, directory, sign-in, RMM and PSA fixtures plus its own `fixtures/licensing/` file and writes canonical JSON, Markdown and a `sha256sum` sidecar. Seats fall in exactly one bucket (orphaned, duplicate, unused, active) so counts add up; the report lists its own reconciliation checks and a test recomputes them from the raw files. Every change is a proposal with evidence and an approver role, `executed` is always false, and the module imports no lever runner, adapter or network module. Dates come from `as_of`. Why: W-VND-01, W-VND-02, W-VND-03, W-BIL-02, W-EP-10; C-21, C-27. Alternative: a `license.reduce` lever (rejected: spending and contract changes are human, W-VND-02). What would change it: a real billing agreement model, a vendor adapter that can price a change (still read-only), a full sign-in activity source, and an audited lever wrapper.
