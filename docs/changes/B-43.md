## Why

On-call engineers should wake up to five grouped events, not fifty alerts. The mock fixes the shape (source types, not products) before any real source exists, and puts the two safety rules in the code every later source inherits: one client per group, and alert text only ever inside an untrusted block.

## DECISIONS proposal

D-0xx Alert grouping is keyed by client, group type and entity, reads no free text, and wraps alert text (B-43, 2026-10-21). A group belongs to exactly one client: other clients' alerts are dropped before keying. Group key = (type, entity kind, entity id, case-insensitive) with a configurable time window (default 60 minutes). Health alerts (RMM agent, endpoint sensor) are their own group type and never merge with incident alerts. Alert title and description appear in a summary only inside `wrap_untrusted`, and are withheld when the injection detector flags them; the alert is still grouped, so hostile text can hide nothing. An alert owned by the external SOC makes its group say the SOC is the responder (D6-04). Why: C-12, C-27, D6-04, W-SEC-01. Alternatives: dropping flagged alerts (a hostile alert would be silenced, which is worse than a withheld description); similarity-of-text grouping (reads untrusted text, harder to explain). What would change it: the MSP's real alert sources and a decision to link user and device entities (B-44).
