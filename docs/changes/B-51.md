## Why

Audit evidence is collected every month, not rebuilt the week before the auditor arrives. Each month, per client: does the audit chain verify, who approved or was denied what, which lever versions existed, which access reviews were done. For the MSP: which changes were merged.

## Individual to macro (L1-L4)

- L1: Lee, a service desk lead, runs one command for October and gets a folder with a hashed manifest instead of screenshots collected under deadline.
- L2: Contoso Dental's bundle holds Contoso's chain summary, Contoso's access review and the levers that may act for Contoso; it names no other client.
- L3: the MSP bundle adds the full registry with lever versions and one change record per merged change, so a lever change (C-37) can be traced to a date, author and file list. Every run, dry or real, is in the scope's own audit chain.
- L4: a small practice's assessor can re-check each file with `sha256sum -c` and each bundle with `verify`, instead of trusting a PDF.

## DECISIONS proposal

D-0xx The evidence bundle is dry-run-first, deterministic and never asserts (B-51, 2026-10-27). A bundle is per period and scope (client, or MSP): hashed files plus a canonical `manifest.json` with a `sha256sum` sidecar. Dates come from `as_of` and from the records, never the clock; the workflow's own audit records are excluded from its counts so a run does not change the next one. `--write` is required to write; a dry run prints the manifest and is audited as a dry run. `verify --audit-dir` requires the manifest hash to be pinned by an execute record in a verifying chain. The manifest carries `management_assertion: not made` and no signature field: a human asserts, outside this workflow. Why: W-CMP-01/04/05/07; C-08, C-37, C-38, C-39. Alternative: a scheduler that signs and publishes monthly (rejected: W-CMP-07 keeps assertions human). What would change it: the assessor's actual evidence request list.
