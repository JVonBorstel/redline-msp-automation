# B-12 change note: repo paths, gateway and guard drift, config version field

Status: **built** (46 tests in `tests/py/core/test_b12_paths.py`). Synthetic data only. No behaviour change on the committed config.

## What changed

- `core/paths.py` (new): `REPO_ROOT`, the single repo-root helper (STD-PY-8, DR-08).
- `core/gateway/config.py`: `GatewayConfig.load(root=REPO_ROOT)` and `GatewayConfig.root` default to `REPO_ROOT` instead of the current directory. New `version: Literal[1] | None` field and `CONFIG_VERSION = 1`. `load` reads `version` from both files and refuses any value other than the integer 1, naming the file (STD-CF-4, DR-07). An absent version is still accepted (tracked, see below).
- `core/gateway/{base,config,gateway,hosted,loopback,mock,ollama}.py`, `core/guard/{wrap,detect}.py`: `from __future__ import annotations` after the docstring (STD-PY-6, DR-14). Two added lines each, nothing else.
- `specs/B-12.md`, `tests/py/core/test_b12_paths.py` (new).

### Outside this item's `owns` (minimal, stated)

- `core/gateway/__main__.py`: `--root` now defaults to `REPO_ROOT` (was `Path(".")`), plus the `__future__` import. Without this, B12-1's "running from another working directory loads the same files" would be false for the CLI, which is the gateway's documented entry point.
- `core/gateway/__init__.py`, `core/guard/__init__.py`, `core/guard/normalise.py`: the `__future__` import only. B12-2 says "every gateway and guard module", and the DR-14 row names `normalise.py`. Proposal: add these four files to B-12's `owns` at the fold.

## Why

Removes working-directory surprises before many new modules depend on them. The same gateway command typed in a different folder could fail or read different files; a config file from a future format could be read as if it were today's.

## Individual to macro

- L1, one person (Priya Nair at Contoso Dental, synthetic): her ticket is classified by the same routed model whichever folder the engineer or the scheduled job runs from, so the triage proposal she gets is reproducible and explainable.
- L2, the client business: a config change (provider or model swap) is read the same way on every machine; a file in an unknown format is refused loudly rather than half-read, so the practice never gets a silently different model.
- L3, the managed service provider (the MSP): one root helper for every new module (DR-08), a version field the reader checks (STD-CF-4), and a uniform module header (STD-PY-6). Fewer "works on my machine" incidents in the shared tooling (`W-TOOL-02`), and change control (`C-16`) can rely on the config's declared version.
- L4, the community: a small, honest example that AI tooling for small businesses can be made reproducible and refuse what it does not understand, rather than guess.

## Honest limits

- **The committed config files still have no `version`.** They are outside `owns`. The loader accepts their absence for now; the test `test_b12_3_absent_version_is_still_accepted_until_owner_wiring` records it, and accepts `1` once the owner adds it. Next step: add `"version": 1` to `config/models.json` and `config/routing.json`, then make absent a rejection.
- **Mixed files:** one file with `version: 1` and the other absent is accepted (tested). Once both carry it, this case also goes.
- **Other loaders** still compute `Path(__file__).resolve().parents[2]`. They are cwd-independent already; they adopt `REPO_ROOT` when next touched.
- **DR-14 is not fully closed**: `evals/injection/report.py`, `evals/triage/__init__.py` and `tests/phase1/test_*.py` are not owned here.
- **`GatewayConfig.model_dump()` now includes `version`** (None today). `workflows/triage/triage.py` dumps and re-validates the config; the round trip is unchanged and its tests pass.

## DECISIONS note proposal

D-0xx One repo root and a checked config version (B-12, 2026-10-21). `core.paths.REPO_ROOT` is the default root for every loader; the gateway config reader accepts `version: 1`, refuses any other value (including look-alikes such as `true` or `1.0`), and accepts an absent version only until both committed files carry it. Why: commands must give the same result from any folder (STD-CF-9), and a reader must refuse a format it does not know (STD-CF-4). Alternative: keep a required `root` argument and no version (simpler, but every caller has to get the root right and a future format is half-read silently). What would change it: packaging the repo as an installed package, where `importlib.resources` would replace a file-system root.
