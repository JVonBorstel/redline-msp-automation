## Results (this machine, 2026-10-27/28, fixture-based)

- 10,000 calls over 300 clients, 3 scenarios (clean, faulty, faulty with 4 threads): 0 chain breaks, 0 cross-client results, 0 double applies, 0 lost jobs. Faulty runs: 9,797 done, 203 dead-lettered (poison jobs plus jobs that exhausted retries); the threaded run reached the same counts as the sequential one.
- Throughput 29 to 38 calls per second end to end, p50 store-call latency 3 to 7 ms. These are dominated by fsync on this disk: see `evals/load/bench_report.md` and its caveats. Not a capacity claim.

## Unverified

- Anything on Linux or a CI runner; the proposed workflow has never run on GitHub Actions.
- Several OS processes writing one database at this scale (threads and one killed child process only).
- Real adapters: the adapter is a SQLite stand-in; a vendor API may not honour idempotency keys.
- The real `LeverRunner` is not in the load loop.
- Timings: one run per scenario, no repeats, no variance.
- Gate thresholds were set from values measured today on mock tiers and hand-written corpora; they are regression alarms, not quality claims.
- The default test run uses 600 calls over 300 clients; the 10,000-call test is opt-in (`B84_FULL_SCALE=1`) and was run once.
- Gate and bench tests were written before their scripts but were first executed after the scripts existed; only the load tests were observed failing first (missing module).

## Findings

Dead letters can have an applied effect; a crash leaves no audit record; the queue has no release-without-penalty so the breaker must be checked before `claim`; no reaper dead-letters a last-attempt lease expiry until something claims for that client. Details in the spec.

## DECISIONS proposal

D-0xx Eval gates are data and fail closed (B-84, 2026-10-27). `evals/gates.json` holds thresholds; a missing result, NaN or crashed source fails its gate. Timings are never gated. Load correctness is gated on invariants of a seeded 120-call run. The CI workflow is a proposal for the owner. Why: C-41, C-17, C-18. Alternative: parse the Markdown reports (rejected: fragile). What would change it: real model evals, a different CI runner.
