## DECISIONS proposal

D-0xx Advisory relevance is a read-only, per-client report with shown factors and no score (B-47, 2026-10-21). A KEV entry matches a device by vendor and product only, because the feed has no version range; each row says the version was not checked. Rows sort by internet exposure, asset criticality, known ransomware use and KEV due date, and print each factor; `rank` is a position, never a score. Scanner and pen-test findings join by CVE and host; a KEV CVE found only by a scanner on an uninventoried host stays on the list with unknown exposure. The emergency list (internet exposed or known ransomware use) carries proposed change windows taken from the client's declared windows and `deployed: false`; the module imports no lever, adapter, network or process code. Why: W-SEC-06, W-SEC-08, W-PAT-05, C-21, C-27. Alternatives: a composite risk score (rejected: an invented number nobody can reconcile); calling the KEV feed live (rejected for now: no network in tests, fixtures pin the date); a deploy lever (rejected: R2 work stays a human decision). What would change it: the MSP's real RMM inventory and product naming, and a real Nessus export to verify the columns.
