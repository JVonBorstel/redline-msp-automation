## Why

The roadmap said the final README and a coverage audit were the last items. A README with hand-typed status goes stale the day after it is written; this one is filled by the tool and a test fails when it drifts. The map had never been checked against the files for status words (only for cross-references, `map/check_map.py`).

## Individual to macro (L1-L4)

- L1: a reviewer sees Priya's whole story in one command and one page, with the limits stated.
- L2: the client's evidence (what exists, what is mock) is stated per control, not claimed.
- L3: the MSP gets a repeatable audit of its own map against its own code, so a status word cannot outrun the tests.
- L4: other small providers can reuse the pattern: generate the status, test the generation, list the gaps.

## Unverified and honest limits

- **The container files were never built or run.** No Docker on the build machine and no network. The base image tag, `pip install uv` and `uv sync --frozen` inside the image, the read-only root with `/tmp` as tmpfs, and the claim that the smoke tests pass inside the image are all UNVERIFIED. The PowerShell suites cannot run in the image (no pwsh).
- The roadmap's "UI on 127.0.0.1 from `docker compose up`" is not delivered: the UI refuses any address but 127.0.0.1 (SC-3), which a container cannot expose to the host without weakening that rule. `up` runs the demo instead. Recorded as a deviation in the spec.
- The audit is static. "Built" means the evidence files exist and a test is tied to the item (owned, named `bNN`, or naming `B-nn` in its first 400 characters); it does not re-run tests or judge them. A test mentioning an id in its header is accepted as tied.
- Inventory status is an upper bound: an item may cover only part of a row. Only rows where every covering item is built are patched.
- A control's "built" needs a cited, existing test file and function. Controls whose evidence is a document or a log are "not demonstrated" even if the process is real.
- The patch was checked with `git apply --check` against a copy of `map/inventory.json`; the owner reviews the proposed wording before applying it. On a CRLF checkout use `git apply --ignore-whitespace`.
- Not run: the demo inside a container, on Linux, or on macOS. The packaged demo was run on the Windows build machine only.
- Python 3.12 via uv's managed interpreter, as in the other suites; the packaged demo needs `uv` only to start it (`python tools/packaged_demo.py` works in any environment that has the locked dependencies).
