# B-56 change note: RAG ingestion with per-client namespaces and vault exclusion

Status: **built** (ingestion, in-memory namespaced store, embedder stand-in, tests). Offline, no model, no network. Synthetic data only. Spec: `specs/B-56.md`.

## What changed

- `rag/` (new package): `rag/ingest/` (`models.py`, `chunking.py`, `screen.py`, `pipeline.py`, `corpus.py`), `rag/store/` (`models.py`, `embed.py`, `memory.py`), `rag/__init__.py` (public interface).
- `fixtures/kb/` (new): synthetic manifests for `contoso-dental`, `fabrikam-capital` and `msp-internal`.
- `tests/py/rag/test_b56_ingest.py` (new): 86 test cases (parametrised), functions named `test_b56_<k>_...`.
- `specs/B-56.md` (new).
- **Outside `owns`:** none. No existing file was edited. Reads, never writes: `core/guard` (redaction gate, data classes, `detect_injection`), `core/audit/router.py` (`valid_client_id`), `adapters/binding.py` and `evals/redaction/clients/` (tests only).

## Why

Retrieval can only be as safe as the index it reads. Isolation by client, redaction, the injection tripwire and the credential-vault rule are applied at write time, before anything is embedded, so a later retrieval bug cannot surface what was never stored.

## Individual to macro (L1-L4)

- L1: Ana, a technician at the help desk, searching for the front-office printer fix finds Contoso Dental's article with its article id, and never a stored password.
- L2: Contoso Dental's chunks are in `client:contoso-dental`; a search for Fabrikam Capital cannot reach them, and the store, not the caller, applies the filter.
- L3: the MSP gets one shared `msp-internal` namespace for runbooks, a report of every refusal by reason, and injection-flagged passages kept as auditable records that cannot be quoted.
- L4: fewer leaks of one practice's or firm's knowledge to another, and no credential vault turned into an AI-readable store.

## Honest limits

- Nothing was run against a real documentation platform or embedding model. The source shape and the vault tag words are conventions chosen here.
- `HashEmbedder` is lexical, not semantic; any quality number built on it is about the stand-in.
- The tripwire and the shape rules are heuristics from B-55 / B-79; a miss is indexed. Vault matching by tag and origin fails closed but cannot see an untagged vault export without secret-shaped text.
- Ingestion writes no audit record, the store is in memory only, and there is no retrieval, citation or leakage eval (B-57).
- "Plus one MSP-internal namespace" is read as one namespace per client plus one MSP namespace; client documents are not copied into `msp-internal`, because B-57's caller-plus-MSP search would then leak across clients. This is a reading for the owner to confirm.

## DECISIONS proposal

D-0xx Ingestion is the isolation boundary for RAG (B-56, 2026-10-27). The namespace is the ingestion job's client; documents cannot choose it. Redaction (B-55) runs before chunking, scanning and embedding; a DC-6 shape or a vault tag or origin refuses the whole source; injection-flagged chunks are stored as records with no text and no vector. Client documents are not copied into `msp-internal`. Embedders are an interface; the only implementation is a deterministic hash stand-in. Why: W-KB-04, W-KB-07; C-26, C-12, C-13, C-25. Alternative: copy every client's documents into `msp-internal` (rejected: caller-plus-MSP retrieval would leak across clients). What would change it: the owner's reading of B56-1, or a real documentation platform's data model.
