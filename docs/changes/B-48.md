## Review fixes (independent review, 2026-10-27)

Behaviour changes, one per finding:

1. Every string taken from a log now goes through the injection detector (`_Ctx.text`/`val`): all firewall fields (`user`, `ui`, `cfgpath`, `cfgobj`, `logid`, `level`, `tunneltype`, `remip`, ...), the audit chain fields (`agent`, `approver`, `lever`, `mode`, `event`, `status`, `actor_kind`) and the alert fields. A flagged value is replaced by the withheld marker and listed in `withheld`. The "human-only" change flag is decided on the raw `cfgpath`, so a withheld value still counts as a rule change. The alert adapter already pattern-checks `entity_id`, so no injection test can reach it there; the scan is applied anyway.
2. Rows with equal time and source sort by the number at the end of the ref (`audit seq 2` before `audit seq 10`), then by ref.
3. A firewall line with no `devid`, no date or time, a bad date or a bad `tz` is dropped and counted in `dropped["firewall-unparsed"]`; the export no longer aborts. Bad bytes in the log are replaced, not fatal. Quoted values may hold `\"` and `\`. A repeated key keeps its first value and each repeat is counted in `dropped["firewall-duplicate-key"]`.
4. New header key `sources` (also in `--text`): for `audit`, `alerts`, `firewall_log` and `tickets` the `status` (`read`, `empty` or `absent`), `count` (rows read) and `in_window` (rows left after `--since/--until`).
5. `--since`/`--until` now mean "at or after"/"at or before" everywhere. The `firewall` pack applies the window to its rows. The `recovery-point` pack takes `--until` as its cutoff (jobs finished, and failures scheduled, at or before it; the output key `before` is now `until`) and rejects `--since`; the `dns` pack is a point-in-time listing and rejects both (exit 2, clear message). Why: the old code used `--since` as an upper bound and ignored `--until`, so the same flag meant opposite things on two packs. The existing test that passed `--since` to `recovery-point` now passes `--until`.
6. The recovery "latest point" is the successful job with the latest `finishedAt` (points are sorted by it), not the last one the adapter lists by start time.
7. The `export` help text no longer says "Markdown timeline"; the default is JSON Lines.
8. An audit record without a usable `ts` or `seq` is counted in `dropped["audit-unparsed"]` and skipped instead of raising. Not done: reading the chain once (verification and row reading still read the file twice; `verify_chain` returns no records, so this is not a small change).

The new tests for findings 1, 2 and 3 (and 4 to 7) were run against the unfixed source and fail there. Vendor log values stay UNVERIFIED.

## Re-review fixes (2026-10-27)

1. `build_pack` carried a fresh context, so the breach pack always showed `withheld: []` and `dropped: {}`. It now adds the timeline's `withheld` and `dropped` to the pack, and passes `firewall_dir` and `devices_path` on to the timeline it builds (the firewall pack already carried its own).
2. `leverExecutes` is decided on the raw audit `mode` (a row flag set before withholding), so a flagged mode cannot hide an execute.
3. A firewall log whose every non-empty line is unparsable reports status `unreadable` (count 0), not `read`. A log of only another client's lines stays `read`.
4. The Markdown section is now "Dropped or withheld", one line per reason with a plain-words explanation (`DROP_REASONS`), so unparsed and duplicate-key counts are no longer called "not this client's".

## One timeline format with B-46

B-46 (PR #60) defined `incident-timeline/1` in `workflows/bec` and asked B-48 to adopt or migrate it. B-48 **adopts it unchanged**: same `format` string, same `notice` sentence, same header keys (`format`, `notice`, `client`, `incident`, `target`, `audit_chain`) and event keys (`at`, `kind`, `source`, `ref`), oldest first, built only after the chain verifies. B-48 only adds keys (header: `window`, `tickets`, `withheld`, `dropped`, `rule_changes`; events: each source's facts). Audit events use B-46's `kind` (`lever.<mode>`) and `ref` (`audit seq N`). No B-46 file was migrated or edited. `FORMAT` and `NOTICE` are kept as constants in `timeline.py` rather than imported, because `workflows.bec` imports the lever runner and this module must not; `test_b48_1_the_export_is_the_incident_timeline_format_b46_defined` fails if they drift from `workflows/bec/config.json`.
