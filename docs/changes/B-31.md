## Why

A new hire's license is a day-one task that waits on someone checking seats, and a departed person's license is forgotten for months. The first becomes a one-click approval that can only use seats the client already pays for; the second is listed and removed only once the retention window is over. Spending stays with the client and a person (W-VND-02).

## Individual to macro (L1-L4)

- L1: a new hire at Contoso Dental (synthetic) can open mail and Office on the first morning. If the company has no free seat of that SKU, the technician is told "no free seat: a purchase needs the client's consent" and nobody is licensed by buying around it. A departed colleague's license ends only after the agreed retention window.
- L2: the practice's seat count rises by one inside what it already pays for; nothing is bought and no contract changes. It stops paying for seats nobody uses once the window has ended.
- L3: the MSP's desk stops carrying a "check seats, then buy if short" chore. Each assignment and removal is a registered, approved and audited change with a dry-run diff; the removal diff names the SKU and the date the window ended, so a billing question has a one-line answer.
- L4: seats are counted per client and never lent between clients; a shortage goes to the client as a decision they make, so there are no bill surprises. The gate that blocks purchase levers is a published list that a reviewer can read.

## DECISIONS proposal

D-0xx License levers use free stock only; a shortage is a message, never a purchase (B-31, 2026-10-21). `license.add` assigns only while `prepaidUnits.enabled` exceeds the SKU's assignments; with none it returns `no free seat: a purchase needs the client's consent (W-VND-02)` and an empty diff. `license.remove` works only when the assignment's `retentionEndsOn` is before the as-of date (the window's last day is still inside it). The never-automate list for W-VND-02 gains `license.buy*`, `license.subscribe*`, `license.add-seat*`, `license.increase*`. Refusals a person must read travel as `data.message` with an empty diff because the PowerShell host reports an error as its type name only. Why: W-VND-02 says spending is human; controls C-05, C-06, C-32, C-35. Alternatives: letting the lever order seats on a "client pre-approved" flag (rejected: consent is a person's act and must be recorded, W-VND-02); a thrown error for the shortage (rejected: STD-ER-5 hides the text). Would change: a vendor adapter that can price a purchase for a recommendation (B-75), still read-only.
