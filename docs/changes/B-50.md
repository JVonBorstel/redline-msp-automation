# B-50 change note

Status: **built** (TenantBaseline drift comparison, report only, tested in `tests/sliceb/Test-SliceB.ps1` section B50; status line added 2026-10-27). Fixture-based; no tenant touched.

- What: TenantBaseline gains `-CompareTo <previous findings.json>`. The report now records a small Conditional Access snapshot (`conditionalAccess`: id, name, state, assignments) so any `findings.json` can be the next run's baseline. With `-CompareTo` it adds a `drift` section (new, resolved and unchanged findings; CA policies added, removed, state changed, assignments changed), a "Changes since previous run" block in `report.html`, and a `drift.txt`. Findings match on `CheckId` plus `Subject`. A previous file without a CA snapshot skips the CA diff with a note; a missing, malformed or other-tenant file throws.
- Report only: drift entries carry no fix lever, mode or target, the drift code never reads `fixLevers`, and the config is untouched (never-automate for CA changes). Default output keeps the same four files and 14 findings on Contoso; the only default change is the new `conditionalAccess` key in `findings.json`. Summary and CSV are untouched, so `Test-SummaryReconciles.ps1` is unchanged.
- Why: a silently weakened policy is noticed the next morning, not months later. This is evidence for the C-21 and C-20 controls (W-IDM-06, W-M365-11).
- Effect (L1-L4):
  - L1 person: the admin sees in one place what changed since the last run, so a switched-off or loosened policy is not missed.
  - L2 business: a weakened Conditional Access policy is caught the next run, not months later; the drift file is evidence for C-21 and C-20.
  - L3 MSP: one repeatable comparison across client tenants, report only, so no tenant is changed and no fix is chosen for the client.
  - L4 community: no effect beyond the repo; the drift method (match on CheckId plus Subject) is plain and reusable.
- Tests: tests/sliceb/Test-SliceB.ps1, section B50 (checks prefixed B50-1, B50-2, B50-3). Includes `B50-3 a default run is byte-identical on a second run` (two default runs, all four files compared by hash).
- Open question for the wave owner: the existing LEGACYAUTH finding proposes `ca.block-legacy-auth`, which matches the `ca.block*` pattern in `governance/never-automate.json`. Left as is (out of scope).
- Decision proposal: "Drift is matched on CheckId plus Subject, never on the numbered Id, and Conditional Access drift is a report, never a lever."
