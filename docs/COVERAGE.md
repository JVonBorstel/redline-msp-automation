# Coverage map: capabilities to repo

Maps every capability in `docs/BLUEPRINT.md` section 2 (scope) to a planned file, the phase that delivers it, and an honest status.

Status words are strict:
- **planned**: not finished. A row that starts "Partly built:" names what exists (code with its test, or a written file) and what is missing.
- **built**: real code with a test that covers it (the row names both).
- **mocked**: runs and is tested, but only against fixtures or fakes (the row names which).
- **document-only**: a written standard or design, no executable code (stated where code would need a real environment).
- **not-planned**: deliberately out of scope, with the reason in the row.

Audit of 2026-10-21 (after Phase 1, Slices A to C, Wave 1, Wave 2 and Wave 3 impact batch 1 (B-68, B-43, B-28, B-39, B-54, B-47); proof only, from the code and test paths named in each row): 52 rows; 5 built, 3 mocked, 44 planned, of which 18 are partly built (counted from the Status column and the "Partly built:" rows). Every statement of what exists names a path. Phase 11 re-audits this file. The coverage audit (`tools/coverage_audit.py`) checks the stated counts against this table.
